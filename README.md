# ボイスティーチング（Voice Teaching）v1.0

**ロボットの教示データ（JOB）を、ふだんの言葉で直す相談ができるアプリ。決めるのは、いつも人です。**

「もう少し上に寄せたいな」と話しかけると、Claude が意味を読み取って「何ミリ動かしますか？」と聞き返します。
「5ミリ」と答えると、Python のプログラムが上限や JOB の形を検査し、3D で変更前と変更後を見せます。
人が画面で **［承認して保存］** を押したときだけ、**シミュレーション用の JOB** を新しいファイルに書き出します。
元の JOB は変えません。実機への接続・転送・ロボットの起動はしません。

> このリポジトリは **Built with Claude: Japan 2026** の提出作品です。
> **2026年11月2日のキックオフ以降に、新しく作り始めました。** 開発の経過はコミット履歴で確認できます。

## 1. 解決したい課題
産業用ロボットの動き（JOB）を少し直すには、今は、ティーチングペンダントで座標・軸・ステップ番号を読み、
数値を手で書き換える必要があります。現場の人は「もう少し上」「ここは3回押してほしい」と言葉では分かっていても、
それを **どの位置の・どの軸を・何ミリ** に置き換えるかに慣れが要り、間違えると気づきにくいのが課題です。

Voice Teaching は、この「言葉 → JOB の変更」の間を手伝います。

- 話し言葉から、**どの位置を・どの向きに・どれだけ** 変えたいかを読み、足りなければ聞き返す
- 変更の候補を **3D と数字（変更前 → 変更後）** で見せる
- 人が見て、画面のボタンで承認したときだけ、**シミュレーション用** のファイルに書き出す

ロボットを直接動かす道具ではありません。シミュレーションで確かめる前の「変更案づくり」を、言葉でできるようにするものです。

## 2. しくみ：Claude は読む、プログラムは確かめる、人が決める
| 役 | すること | しないこと |
|---|---|---|
| **Claude**（Claude API・構造化出力） | 話し言葉から、意図・対象の位置・方向・量・足りない項目を読む。足りなければ聞き返す。会話の続き（「5ミリ」）をつなぐ。JOB について質問に答え、人が教えた意味（「これはボタンを押す動き」）を覚える | 数の計算・単位の換算・安全の判定・承認・出力 |
| **プログラム**（Python） | Claude の読みを独立に確かめる（根拠の言葉が本当に発話にあるか・量は自分で読み直して mm に換算・位置は JOB の一覧と照合）。1回 20mm・累計 20mm の上限、座標系、共用の位置、JOB の形、差分を検査する。出力の中身を作る | 推測で量や軸を決めること |
| **人** | 3D と変更前 → 変更後を見て、名前を入れて画面のボタンで承認する。上・下・右・左が軸のどれかは、ボタンで確かめる | 声だけの承認（できません） |

- 「少し」「くらい」など、数のない量や「だいたい」の量では候補を作りません（聞き返します）
- 候補や承認のあとに、言い直し・否定・ためらいがあれば、古い候補と承認は使えなくなります（取り消し、または保留）
- Claude につながらないときは、黙ってモックに切り替えません（理由を出して止めます）
- 使うモデルは `ANTHROPIC_MODEL`（`.env.example` では `claude-sonnet-5-5`）。書かなければ、解釈は `claude-opus-5-5`、説明は `claude-sonnet-5-5`

### できる変更（v1.0）
| 変更 | 言い方の例 | 決め方 |
|---|---|---|
| 位置の移動（X・Y・Z） | 「C00004 を Zプラス方向に5ミリ動かして」「もう少し上に寄せたいな」→「5ミリ」 | 1回 20mm まで。上・下などの向きはボタンで確かめる |
| 区間を通る回数 | 「C00001からC00003の作業を2回から3回にして」 | 範囲は［この範囲を繰り返す］のボタンで決める。同じ動きを足すだけで、新しい位置・新しい移動の線は作らない |

1回の指示では、1つの変更だけを扱います。

## 3. 3D で変更を確かめる
- 読み込んだ JOB の位置（C00000…）と移動の線を 3D で描きます。ドラッグで回し、ホイールで拡大できます（Y-Z・X-Z・X-Y の面の表示もあります）
- 候補ができると、**変更前（灰）と変更後（オレンジ）** の点と線、変更の大きさの拡大の窓（例：Z +5.000mm）、回数の窓（例：×2 → ×3）が出ます
- 候補の窓には、対象の位置・JOB の名前・「シミュレーション用（実機への接続・送信はしません）」・変更前 → 変更後の数・注意を並べます
- ［変更前を再生］［変更後を再生］で、動きの順番を見比べられます
- **図は目安です。** 長さは実寸ではなく、ロボット本体・関節・周りの物は描いていません。干渉や安全を確かめるものではありません

## 4. 承認して保存
1. 候補の窓と 3D を見て、承認する人の名前を入れ、**［承認して保存］を1回** 押します（声では承認しません。名前が空なら承認しません）
2. サーバーが、承認が今の候補のものかを確かめ、通ったらシミュレーション用の JOB を書きます
   - アプリの記録（控え）：`output\sim\<JOB名>_SIM_YYMMDDHHMM.JBI`（日本時間・分まで。同じ分なら `_02`・`_03`。上書きしません）
   - 中のジョブ名（`//NAME`）は `<JOB名>_SIM`
3. 続けて、保存の場所を選ぶ窓が開きます（Chrome・Edge）。選んだ場所に同じ中身を書き、**読み戻して同じと確かめてから** 「保存しました」と出します

保存の結果は、次のように言い分けます（成功の ✓ は、選んだ場所に保存できたときの1つだけ）。

| 場合 | 見出し |
|---|---|
| 選んだ場所に保存し、読み戻しも同じ | 保存しました |
| 窓を閉じた・書けなかった・読み戻しが違う | 出力しました（保存先にはまだ保存していません）。もう一度承認しないで［保存先を選んで保存］で保存し直せます |
| 窓が使えないブラウザー | 出力しました（ダウンロードはブラウザーで確かめてください） |
| 承認のあとに話しかけて保留になった | 取り消すか確かめています（承認・出力はできません）。保存のボタンも押せません |

書いたファイルはシミュレーション用です。拡張子は `.JBI` ですが、**実機には入れないでください**（名前と中のジョブ名に `_SIM` が付きます）。

## 5. 安全上の制限と、まだできないこと
### このアプリがしないこと
- ロボットの起動・実機への接続・JOB の転送。実機用の出力の機能はありません
- 元の JOB の書き換え（いつも新しいファイルに書きます）
- 声や文字での承認・出力

### 制限
- 移動は1回 20mm・累計 20mm まで（**仮の値**。現場の確認待ち）
- 「上に」「下げて」を Z＋・Z− として読むのは、専門家が確かめて登録した設定（既定 `records/updown.json`。git に入りません）に合うときだけ。無ければ、そのたびにボタンで確かめます
- 回数の変更は、同じ移動の区間（1回分 2〜10 行）が続けて2回以上書かれた JOB だけ。信号（DOUT）や待ち時間（TIMER）を含む作業は対象外です
- 扱える命令や位置の書き方には限りがあります。分からないものがあれば、変更せずに止めます（`samples/dummy/PATTERNS.md`）

### まだできないこと・分かっている弱点
- 専門家が位置ごとに決める枠（FRAME）・干渉の確認・ロボットの関節の計算はしません
- **検査を通ることは、物理的な安全の保証ではありません。** シミュレーションと現場の人の確認が必要です
- 画面の幅が 1500px 以上のとき、承認して保存のあとに話しかけると、答えや選ぶボタンを見せるため、候補の窓が 3D の右下に移り、変更の点にかかることがあります
- 保存の場所を選ぶ窓は Chrome・Edge だけ。ほかのブラウザーでは、ダウンロードとして保存します
- Claude につながらないとき（モック）は、決まった言い方しか読めません（「3センチ」「寄せたいな」は聞き返します）
- 内部のテストと、同じ AI による確かめは行っていますが、**独立した第三者の安全の確認ではありません**

## 6. 起動（Windows・PowerShell）
### 必要なもの
| もの | 版 |
|---|---|
| Python | 3.11 以上（3.13 で確認） |
| Chrome | 最新（音声入力は Chrome の音声認識） |
| Claude API のキー | 本物の Claude で動かすとき |
| Node.js・Playwright | テストだけ（任意） |

### 本物の Claude で起動する
```powershell
git clone https://github.com/RyutanCAMP/voice-teaching.git
cd voice-teaching
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env          # .env に自分のキーを書く（下の「環境変数」）
python -m voice_teaching.claude_check   # キーの置き方の点検（通信しない）
$env:PYTHONUTF8="1"; $env:PYTHONIOENCODING="utf-8"
python -m voice_teaching.web --port 8901 --channel filming
```
- Chrome で **http://127.0.0.1:8901/** を開きます（エディターの中の画面では、音声が使えないことがあります）
- 起動の窓に「解釈：本物の Claude」「意味理解（Claude）：準備ができました」と出れば準備完了です（最初の1回は 30〜40 秒）
- キーが無い・`.env` が読めないと、`--channel filming` では起動しません

### キーなしで試す（モック）
```powershell
python -m voice_teaching.web --mock      # http://127.0.0.1:8765/ ・本物の Claude を呼ばない・.env を読まない
```

### 環境変数（`.env` に書く。`.env` は `.gitignore` で除外され、GitHub に上がりません）
| 名前 | 内容 |
|---|---|
| `ANTHROPIC_API_KEY` | Claude API のキー（必須。本物の Claude のとき） |
| `ANTHROPIC_MODEL` | 使うモデル（任意） |
| `VOICE_TEACHING_API_BUDGET_USD` | 料金の上限（米ドル・任意・既定 5）。すべての呼び出しを `records/api_usage.jsonl` に記録し（送った中身・キーは書きません）、累計が上限を超えそうなら呼びません |
| `VT_CHANNEL` | 画面の版の区別（`dev`／`filming`／`release`。`--channel` と同じ・任意） |

キーをコード・コミット・チャット・スクリーンショットに書かないでください。

## 7. デモの手順（合成 JOB・`samples/dummy/`）
`samples/dummy/` の JOB は、このリポジトリで作った架空のデータです（実機のデータではありません）。

### A. 位置を少し上へ（`DEMO_RJ_XYZ.JBI`）
1. JOB をドロップする。3D に位置と線が出ます
2. 位置 **C00004** を押して選ぶ
3. 「Zプラス方向に3センチ動かして」→ 上限 20mm を超えるので止まります
4. 「もう少し上に寄せたいな」→「何ミリですか？」→「5ミリ」（向きを聞かれたらボタンで答える）
5. 候補の窓の **Z 180.000 → 185.000** と、3D のオレンジの点・拡大の窓（Z +5.000mm）を見る
6. 名前を入れて **［承認して保存］** → 保存の場所を選ぶ → 「保存しました」

### B. ボタンを押す回数を 2回 → 3回（`DEMO_BUTTON_REPEAT.JBI`）
1. JOB をドロップする
2. 「このロボット、何をしている？」と聞く → Claude が JOB の動きを説明します
3. 「ボタンを押してるんだよ」と教える →［この動きです］で、どの動きかを決める
4. 「じゃあ、3回にして」（または「C00001からC00003の作業を2回から3回にして」）
5. 範囲を見て **［この範囲を繰り返す］** を押す
6. 候補の窓の **合計 2回 → 3回** と、3D の「×2 → ×3」を見る → 名前を入れて **［承認して保存］**
