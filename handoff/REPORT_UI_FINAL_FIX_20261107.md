## 2. XC-28（最優先）保留中に「承認・出力はできません」と出ているのに、保存のボタンが押せた
### 状態の整理（事実）
- 保存のボタン（［保存先を選んで保存］［ダウンロードとして保存］）が保存するのは、`state.lastExport` の中身だけ
  - これは、承認のあとにサーバーが書き出した JOB（アプリの記録の控えと同じ。sha256 で読み戻しを確かめる）
  - **新しい変更や承認していない中身を保存する道は、前から無い**（ボタンはサーバーに何も送らない。書き出しは承認のあとの1回だけ）
- つまり XC-28 は「承認した中身の保存し直し」が、保留中にもできてしまうこと。見出し・説明と動きが食い違っていた
- 保留が終わると：
  - ［このまま残す（もう一度承認）］は、承認を取り消して候補を残す
  - ［取り消す］は、承認と候補を取り消す
  - どちらも結果の欄ごと消える（`exportOwner`。前から）。保存し直すには、もう一度［承認して保存］する

### 直し（app.js）
- 保留中・閉じた画面では、保存のボタンを2つとも押せなくする
- 結果の欄に、黄の文でわけを書く：「保留中は保存できません（取り消すか確かめています）。［このまま残す］を選んだら、もう一度［承認して保存］してください」
- `saveToChosenPlace`・`downloadFallback` の頭でも同じ条件で止める（JS からボタンを押しても保存の窓を開かない）

## 3. 回数の変更（2回 → 3回）を承認して保存したあと、3D の「×2 → ×3」が隠れた（UX-2100-P1-1）
- 原因：UI-1700-1 で残した例外（承認のあとに答えが出ている間は、候補の窓を 3D の右下へ）。回数の変更では、承認の前の答え「これでいいですか？」が承認のあとも出たままなので、例外がいつも効いていた
- UX 点検の差分（例外を外すだけ）を試したら、「ありがとう」など**承認のあとに出た新しい答えが、候補の窓の下に隠れて読めなくなった**ので、そのままは使わなかった
- 直し（最小）：答えに「承認のあとに出た」印を付け（`showReply` で `data-after-approval`）、例外はその印があるときだけ効かせる（style.css のセレクター1つ）
  - 回数の変更のあと：候補の窓は会話の欄の上のまま → 3D の回数の窓「×2 → ×3」と札「C00001〜C00003 ×2 → ×3」が見える（3つの大きさ）
  - 承認のあとに話しかけた答え：前のとおり、答えが読める
- `tools/check_approve_save.py` に3件足した（3つの大きさで、候補の窓の下に 3D の点と「×3」が無い）。**b78dad5 では 1920 で NG**（2つとも隠れる）
  - 数えるのは 3D の表示の中のものだけ（回数の変更の向きでは、台座の印が 3D の表示の左の外に来て、もともと見えないため）

## 4. XC-29（承認して保存のあとに話しかけると、1920 で 3D がまた隠れる）— **今回は保留**
- 2つの場合がある
  - 「どこが変わったの？」→ 保留になり、答えに［取り消す］［このまま残す］が出る。押す必要があるボタンを隠さないため、クーちゃん K1 の例外で候補の窓は 3D の右下に行く
  - 「ありがとう」→ 答えだけ。いちばん新しい答えを隠さないため、11/7 の例外で 3D の右下に行く
- どちらも「会話（ボタン・答え）を見せる」か「3D を見せる」かの取り合い。両方を守るには、候補の窓の置き場所か大きさを新しく決める必要があり、小さな直しでは済まないので、指示どおり保留にした
- クロークの ui_polish_check V2 は b78dad5 と同じ結果（「どこが変わったの？」「ありがとう」で FAIL・新しい候補で PASS）
- 撮影の台本の流れ（保存 →「3ミリに訂正」＝新しい候補）には出ない
- 案（次に直すなら）：承認のあとは候補の窓を小さくし（承認の印・結果の欄・［元に戻す］だけ）、3D の右上の拡大の窓の下に置く
