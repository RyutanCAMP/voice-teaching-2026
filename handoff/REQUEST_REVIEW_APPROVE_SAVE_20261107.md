## 変えたこと（短く）
1. **［承認して保存］**：候補の窓の横（と［詳しく見る］の中）のボタン1つ。押すと
   ① `/api/approve`（サーバーが候補の世代・保留・上下の向き・止まった候補・名前を確かめる。今のまま）
   ② 通ったときだけ続けて `/api/export`（合成 JOB だけ・中身の検査・上書きしない。今のまま）
   ③ 保存の場所を選ぶ窓（`showSaveFilePicker`）→ 書いて読み戻し、sha256 が同じときだけ「保存しました」
2. 保存の窓を閉じた・書けない・読み戻しが違う → 保存したと言わない。**もう一度承認せずに**［保存先を選んで保存］（②で書いた中身を使う）
3. ②が断られたときだけ［保存をやり直す（承認はそのまま）］（同じ承認で②をもう一度）。ふだんは最後の出力のボタンは無い
4. 名前：`<JOB名>_SIM_YYMMDDHHMM.JBI`（日本時間・分まで。同じ分なら `_02`・`_03`…。上書きしない）。中の `//NAME` は `<JOB名>_SIM`
5. e2e の今までの確かめは、`server.AUTOSAVE_DEFAULT = False`（e2e の中だけ）で、承認のあと［保存をやり直す］のボタンで書く形で流す。**本番の起動はいつも True**

## クローク（回帰）にお願いしたいこと
- 連打（［承認して保存］の2回押し・ダブルクリック）：承認の送信1回・書き出し1回か
- 保存の窓のキャンセル・保存のエラー・読み戻しの違い → 保存したと言わないか、もう一度承認せずに保存し直せるか
- 同じ分の2回目 → `_02`。前のファイルが変わらないか
- 古い候補の失効（言い直し・否定・位置の選び直し・JOB の読み直しのあと、［承認して保存］が押せない／サーバーが断るか）
- 20mm・累積・共用・座標系・2→3回、承認した内容と `.JBI` の中身の一致、元の JOB が変わらないこと
- 3つの大きさで［承認して保存］と注意が見えるか
- OS の本物の保存の窓は自動で操作できない：手で確かめる手順は REPORT の 4章
- 自分で書いたコードの確かめは独立のレビューと呼ばない（いつもどおり）

## クロ（独立の安全レビュー）にお願いしたいこと

  （画面の流れだけでなく、`/api/approve`・`/api/export` を直接呼んだとき・2つのタブ・遅い応答）
