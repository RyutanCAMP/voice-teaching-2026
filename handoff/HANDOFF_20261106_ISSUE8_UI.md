## 3. UI-1（承認のあとの保留）
- 決まり（唐川さん main 1e7aa98）：緑の ✓ は `approval && !hold && can_export` のときだけ
- 画面（app.js `renderApproval`）：緑の「✓ 〜さんが承認しました」と承認のあとの3つの状態は、`approval && !hold && 画面が終わっていない && (can_export || 実機の JOB の確認のみ)` のときだけ。
  保留中は黄の「⚠ 保留中：承認・出力はできません（取り消すか確かめています）」、閉じた画面は「この画面は終わりました（承認・出力は使えません）」
  - **確認してほしい**：実機の JOB（合成ジョブでない・`exportable: false`）を承認したときは `can_export` がいつも false なので、文字どおりの決まりでは緑にならない。今までどおり緑の ✓ ＋「変更案の確認のみ。実機用JOBは出力できません」のままにした（保留・取消ではないため）。緑にしない方がよければ直す
- **サーバーの文を変えた所（独立の Safety レビューにかける）**：`voice_teaching/web/flow.py`
  1. `talk()` の「承認のあとの相づち」の道（route `approved`）：保留中（`e.hold`）なら `STEP_F_APPROVED_NEXT`
     「承認済みです。出力は画面の［シミュレーション用に出力］のボタンで行います（声や文字では出力しません）」の代わりに、
     既にある `M_HOLD`「取り消すか確かめている変更候補は、承認・出力できません。「取り消して」か「このままでいい」で答えてください」
  2. `_status_line`（アプリの記録の1行。画面ではアプリ情報の中）：承認の記録があっても保留中は「承認 済み（ボタンで承認）」でなく「承認 保留中（承認・出力はできません）」
  - 保留・承認・出力・候補の無効化の判定と条件、`can_export` の計算、`stale.py` の言葉の一覧は変えていない
- 画面の見せ方：1100〜1499px（1280×720・1440×900）の保留中は、候補のポップアップを中身の高さにして、下の返事のカードを隠さない。返事の選択肢の文字は折り返す
- 残り：「ちょっと待って」の返事のカードの見出しは、返事の status が `stop` のため「この指示は使えませんでした。言い方を変えて、もう一度どうぞ」のまま（a044212 と同じ）。
  本文は出力を勧めない文になった。［取り消す］［このまま残す］のボタンは「ちょっと待って」では出ない（返事の形を変えないため）。どちらも直すなら唐川さんの判断
