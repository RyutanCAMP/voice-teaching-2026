## 3. 入れたもの
### 3-1. Claude を意味理解の中心に（新）
- `voice_teaching/nl_understand.py`・`ClaudeInterpreter.understand`：構造化出力（JSON Schema・effort medium）で、意図・位置・方向・量・足りない項目を返させる。例（few-shot）5つ、Python が作る状態（位置の一覧・選んでいる位置・直前の候補・聞き返しの途中・直近の会話の文）を渡す。座標の値・ジョブの中身・キーは送らない
- **Python の独立の確かめ**：根拠の文字列が今の発話にあるか／量は Python が根拠から読み直し、mm・cm を換算して Claude の値と合うときだけ使う／位置はジョブの一覧／方向の言葉が根拠にあるか／「少し」「くらい」は数にしない
- 会話の枠：「もう少し上に寄せたいな」→「C00004 を上にですね。何ミリ動かしますか？」→「5ミリ」→ 決まった文「C00004を5ミリ上げて」
- **そろったら決まった文にして、今までの道にそのまま通す**：pre_check → 上下・右左の向きの確かめ（ボタン）→ 解釈の係 → check_proposal → jbi（20mm・累積・共用・座標系・構造）→ 差分 → 画面のボタンで承認 → 合成 JOB の SIM 出力。**安全の判定・承認・出力のコードは変えていない**
- 使う場面：本物の Claude のときだけ。はっきりした指示・否定・承認や出力の言葉・上下の案内・速度・回数・候補や承認があるときは、今までの道（Claude の意味理解は呼ばない）
- 接続の失敗と形の崩れを別の文にした（「ネットワーク」と「答えの形が崩れていました」）
- 起動のとき1回だけ空呼び（最初の1回の約38秒を画面で待たせない）
