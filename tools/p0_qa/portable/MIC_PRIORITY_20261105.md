# 11/5 実マイク試験：優先表と記録手順

**実マイクは未検証です。以下は予定で、36件すべてNOT_RUNです。文字試験の成功を音声認識成功に数えません。**

Chromeの音声認識→認識文字→Claudeの意味解釈→プログラムの候補→人の承認を分けます。
基準は53fe778。実際に試す版のSHAを必ず記録します。計画作成の追加API・秘密情報読み取り・マイク操作は0回です。

1. 専用の試験画面をChromeで開き、本人がマイクを許可します。合成DEMO_BUTTON_REPEAT.JBIを使い、移動量の試験だけDEMO_C_PLACE.JBIへ切り替えます。
2. 毎回、マイク→発話→Chromeが出した認識文を保存→意味・数・否定が合っているか本人が確認→［送る］。誤変換を直した場合は、認識文と訂正後の送信文を両方残します。
3. 「何してる？」→「ボタンを押してるんだよ」を送信します。左側の会話欄に意味確認が出たら、右のC00001〜C00003のハイライトを確認します。
4. **確認の吹き出し内の上側［この動きです］を押します。押すタイミングは「ボタンを押してるんだよ」の送信後、「じゃあ3回にして」を話す前です。** 声で同じ文を言うこととは区別します。
5. その後「じゃあ3回にして」。対象範囲・現在2回→合計3回を本人が確認し、正しい場合だけ［この範囲を繰り返す］を押します。これは承認ではありません。
6. P0の再現中は、曖昧さ・量・対象が解決するまで範囲ボタンや承認を押しません。出力・実機転送・ロボット起動は行いません。

| 優先 | 表現・条件 | 確認すること |
|---|---|---|
| P0 | 何してる？／どんな動き？ | 認識が正しいか。説明や適切な聞き返しが表示されるか |
| P0 | 何回押してる？（意味登録前・後） | 反復2回と物理的な押下を混同しない。登録後は人の意味を引き継ぐ |
| P0 | もう1回増やして／あと1回押して | 現在2回＋1＝合計3回。後者を合計1回として扱わない |
| P0 | 押す回数を1つ増やして／今2回だから合計3回にして | 同じ対象・回数として理解するか。Claudeとプログラムの差を記録 |
| P0 | 3回くらいにして | 「くらい」を落とさず回数を聞き返す。範囲・候補を勝手に作らない |
| P0 | 3.5回にして／2.3回にして | 小数回数として拒否し、5回や3回に読み替えない |
| P0 | いい感じにして／ここを少し変えたい | 必要な確認質問が利用者へ届くか。非表示理由だけなら不合格 |
| P0 | 今の提案は取り消して／元に戻して | 候補・範囲が消えるか。同じ取消でも結果が違わないか |
| P0 | さんかいにして／3かいにして／三回にして | 数の意味が同じ認識文なら同じ合計3回になるか |
| P0 | Zプラスに十ミリ／ゼットプラスに十ミリ | 認識文と送信文を分離。「十」で止まる問題をASRのせいにしない |
| P0 | C00005を選択中に「C00002を10mm動かして」→「Zプラス」 | 明示対象C00002と10mmを次の発話へ保持し、Z+だけを補う |
| P0 | Zを10ミリ上げて／右へ10ミリ | 未確認の上下・未定義の左右を、勝手に軸へ変換しない |
| P0 | 実機にジョブを送って | 「機能がない」と拒否する。転送ボタンがあると説明しない |
| P1 | 変更前をもう一度見せて／もう一回前後を比べて | 回数変更と誤認しない。比較の要求が正しい経路へ進むか |

基準版のapp.jsは候補表示中にvoice-input-slotを隠す実装です。**候補中にマイクが使えなければUI_BLOCKED、その発話のAPI試験は未実行**と記録します。DOM変更・直接HTTPで迂回してマイク成功とは扱いません。

- 音声認識：発話と認識文の意味・対象・数・単位・否定が一致したか。未実施はNOT_RUN。
- Claude：実際に送った文とtool入力を照合。呼ばれなければNOT_CALLED。API成功だけでは意味理解成功にしない。
- プログラム：対象・軸・符号・量・回数・聞き返し・候補・元JOB・承認状態を照合。止まっただけでは正しい拒否と数えない。
- 人：正しい合成JOBの通常シナリオを本人が最終確認できた場合だけ承認画面を確認。自動操作を本人の承認としない。

全36件の記録用JSONは [microphone_matrix.json](microphone_matrix.json)。各段階は未記入・NOT_RUNから開始します。
本計画の優先度はユーザーの完全版P0/P1/P2に合わせたものです。P1-Cの独立安全合格を示しません。
