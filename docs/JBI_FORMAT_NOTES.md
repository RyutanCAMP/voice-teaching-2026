# JBIの書き方：前提と確認待ちの点

`samples/dummy/` のジョブは、このリポジトリで新しく作った**架空のジョブ**です（実機のジョブではありません）。
安川のJBIの一般的な書き方をもとにしています。次の点は、実機で作ったサンプルで確認してから確定します。

| 前提 | 状態 |
|---|---|
| 位置は `//POS` の中に `C00000=X,Y,Z,Rx,Ry,Rz` の形で並ぶ（HC20 は6軸なので、ロボット座標の位置は値が6個） | 確認待ち |
| `///POSTYPE ROBOT` と `///RECTAN` のとき、位置はロボット座標（mm・度） | 確認待ち |
| **教示位置がパルスで保存されるか、ロボット座標で保存されるか**（最重要。パルス保存ならこのアプリは位置を変えられない） | 確認待ち |
| POS内の指示行（`///POSTYPE`・`///RECTAN`・`///PULSE`・`///TOOL`・`///USER`・`///RCONF`）は、その後ろの位置に効く。`///POSTYPE` で RECTAN は解除される | 確認待ち |
| 命令は `//INST` の下に1行ずつ並び、`MOVL C00003 V=80.0` の形で書かれる。行の前後に空白は無い | 確認待ち |
| INST部の `///LVARS` は数字をカンマで区切った形（例 `///LVARS 0,0,0,0,0,0,0,0`）。一般的な書き方に基づく前提 | 確認待ち（実機サンプルで確認） |
| 直線速度 `V=` の単位 | 確認待ち（表示単位の設定で変わる可能性） |
| `PL=` が付くと角を内回りする | 確認待ち |
| 文字コード（Shift_JIS を想定。ascii → utf-8 → cp932 の順に試し、書き戻して元のバイト列と一致するときだけ扱う） | 確認待ち |
| ジョブ名の文字数の上限 | 確認待ち |
| 改行コード | 読み込んだファイルのものをそのまま保つ |

## このアプリの方針
- 分からない行は、**一文字も変えずにそのまま残す**
- 変えるのは、検査を通った位置の数値1つだけ（速度の変更は今は止めている。下の「速度の変更」を参照）
- 変更はまず変更案（`ChangeProposal`）として作り、元のジョブは変えない。変更後の値は、新しいジョブを読み直した実際の値を出す
- 命令を「認識できる」ことと「変更を許可する」ことは分ける。知らない命令や読めない行があっても、読み込みは最後まで行い（位置・命令・problems を表示できる）、変更は problems で止める

### INST部の命令の許可リスト（仮。実機サンプルで本人と確定する）
推測で増やさず、今のコード・ダミー・仕様に出てくるものだけを入れている。これ以外の命令は problems に入れて、変更をすべて止める。
- `NOP`・`END`・`MOVL`・`MOVJ`・`MOVC`・`MOVS`・`DOUT`・`TIMER`・`JUMP`・`CALL`・`RET`
- ラベル行（`*` で始まり、ラベル名だけの行。例 `*L1`）
- コメント行（`'` で始まる行。命令としては扱わない）
- 止めるために知っている命令（ジョブにあれば位置の変更を止める）：`SFTON`・`SFTOF`・`MSHIFT`・`MFRAME`・`IMOV`・`SMOVL`・`SMOVJ`・`SMOVC`・`SMOVS`
- `GETS`：止める命令ではない。位置を参照する命令として「使う行」に数え、その位置は共用・MOVL でない で止まる

追加の候補（`WAIT` など）は、実機のJBIで確認してから判断する。今は入れていない。
大文字小文字は区別する（`nop`・`movj` などは許可リストに無い命令として止める）。
引数の形まで決まっている命令は、先頭の語だけでなく**行全体の形**で判定する（QA 3回目 P2-1。`END X`・`NOP X`・`TIMER T=I000` などを止める）：
- `NOP`・`END`：引数なしだけ
- `TIMER T=数値`（`T=` の後ろは ASCII の数字と小数点だけ。変数 `I000` などは止める）
- `DOUT OT#(番号) ON` / `DOUT OT#(番号) OFF` だけ（`OG#`・数値の出力などは止める）
- 移動命令・`JUMP`・`CALL`・`RET`・`GETS`・止める命令は先頭の語で判定する（移動命令は、対象・入る区間の始まり・出る移動の許可リストで別に判定する。JUMP などはジョブにあれば位置の変更を止める）

### ジョブ全体を止める（変更をすべて断る）もの
次のどれかがあれば、ジョブを「読めない所がある」（problems）として、変更しない。
- POS部の読めない行（`BC`・`EC` などの行を含む）
- 位置の値に数値でないものがある（`nan`・`inf`・`1_000` なども数値とみなさない）
- 位置の値が3個未満
- 同じ名前の位置が重複している
- INST部の `///GROUP1 RB1` 以外の GROUP 行（複数の軸グループ）
- INST部の許可リストに無い命令（上の一覧）
- 前後に空白（半角空白・タブ）がある行、空の行
- 全角空白（U+3000）・NBSP などの空白文字を含む行（コメント行 `'` と `///COMM` を除く）。読み込みは最後まで続ける
- END より後ろにある命令（実行されない命令。その命令だけが使う位置を取り違えないよう、ジョブごと止める。END の後ろのコメント行は問題にしない）。引数の付いた `END X` も END とみなして、その後ろを止める
- END の命令が無いジョブ（途中で切れたファイルかもしれないため。QA 3回目 P3）。`//INST` が無いジョブも同じ
- 位置の行・命令の行に ASCII 以外の文字（全角の数字 `４５０`、アラビア・インドの数字など）がある（QA 3回目 P2-3。数字は ASCII の `0〜9` だけを数字として扱う。コメント行 `'` と `///COMM` は除く）
- 位置の値の整数部が7桁以上（このアプリで扱える桁を超える。桁あふれ・inf を防ぐためのもので、ロボットの動作範囲を決めるものではない）
- （原本より厳しい追加）`//NAME`・`//POS`・`//INST` 以外の見出し（`//ALIAS` など）や、同じ見出しの重複
- （原本より厳しい追加）INST部の `///DATE`・`///ATTR`・`///COMM`・`///GROUP1 RB1`・数字をカンマで区切った `///LVARS` 以外の指示行（`////FRAME ROBOT` は下の条件のときだけ認める）
- 相対ジョブの FRAME の行（CHECKER_027 X2。唐川さんの決定 2026-11-03）。次の**すべて**を満たすときだけ、`////FRAME ROBOT` を知らない指示行にしない。ジョブには「相対ジョブ（ROBOT 座標）」の印（`Job.relative_frame == "ROBOT"`。problems ではない情報）が付く
  1. 行がちょうど `////FRAME ROBOT`（斜線4本・値 ROBOT・後ろに何も付かない。前後の空白は今どおり problems）
  2. `///POSTYPE ROBOT` と `///RECTAN` があり、どの位置も ROBOT・RECTAN（`///PULSE` やほかの POSTYPE があれば止める）
  3. `///ATTR` の行が1つで、その並びの1つに `RJ` がある（`RJX`・`rj` は認めない）
  4. `///USER` の指定が無い
  5. FRAME の行は1回だけで、INST部の指示行の並び（`///ATTR` の後、命令・コメントより前）にある
  - `///ATTR` に RJ があるのに FRAME の行が無いジョブも止める（CHECKER_028 K3・F4。「相対ジョブ（RJ）ですが、座標系（FRAME）の行がありません」）
  - 止めるもの（problems に入れ、どの条件に合わないかを書く）：`////FRAME USER 1`・`////FRAME BASE`・`///FRAME ROBOT`（斜線3本）・`/////FRAME ROBOT`・`////FRAME ROBOT X`・小文字・2回・ROBOT とほかの FRAME の両方・RJ なし・POSTYPE USER／PULSE・RECTAN なし・`///USER` あり・`///ATTR` より前・命令より後ろ・POS部にある FRAME の行
  - 斜線4本の意味は公開資料では未確認（実機の2つのファイルとペンダントの表示から、相対ジョブの座標系の行として扱う）
  - FRAME の行を認めても、ほかの検査（MOVL 以外・PL>0・MOVJ の隣・共用・許可リスト・TOOL・RCONF など）は省かない。相対ジョブは行き先がツールのファイルにも左右されるので、変更案の「ツール番号」の注意は今どおり出す
- （原本より厳しい追加）`///NPOS` が無い、読めない、または位置の行の数と合わない
- （原本より厳しい追加）行の中のタブ以外の制御文字や、`\n` を伴わない `\r`

### 位置の変更（`plan_shift`）を断るもの
- 上の「ジョブ全体を止める」ものがある
- 移動量・上限の引数が bool、0、有限でない（nan・inf）、大きすぎて扱えない（巨大な整数）、数値でない
- 1回の移動量が上限（`DEFAULT_MAX_SHIFT_MM = 20.0`。仕様v2.1 のデモ案の「1回の上限 20mm」。最終の値は本人が実機を見て決める）を超える。丸めた後の実際の移動量も確かめる。引数 `max_abs_delta_mm` は上限を下げる方向にだけ効く（大きい値を渡しても 20mm のまま）
- 元のジョブ（基準）からの**累積**の変更量が、軸ごとに上限（20mm。1回の上限と同じ値）を超える（仕様v2.1 6章「基準からの累積で軸ごとに検査」）
- 位置が無い、軸が X・Y・Z 以外
- 位置がロボット座標でない（位置ごとに判定する）。知らない指示行、または想定外の引数が付いた指示行（`///RECTAN 1`・`///PULSE 1`・`///TOOL A` など）より後ろの位置も変えない
- ロボット座標の位置の値が6個でない（HC20 は6軸。7個以上・3〜5個は止める）
- ジョブに `SFTON`・`MSHIFT`・`MFRAME`・`IMOV`・`SMOVL/J/C/S` がある（原本より厳しい追加：`SFTOF` も止める）
- ジョブの中に `JUMP`・`CALL`・`RET`・ラベル行が1つでもある。制御の流れを解析する機能がまだ無く、入る移動・出る移動が無関係だと確かめられないため（本人の判断）
- 位置がどの命令にも使われていない
- 位置を2つ以上の命令が使っている（共用。行番号を示す）
- 位置を使う命令が「`MOVL 位置 V=数値`」または「`MOVL 位置 V=数値 PL=0`」の形でない（MOVL以外、同時移動、PL=1以上、緩い書き方の PL、CR付き、知らない語が付いている）
- 入る区間の始まり（対象のMOVLの直前の移動命令）が「`MOVL C位置 V=数値`」または末尾にちょうど ` PL=0` の形でない。変数の位置（`P000`・`LP000`・`BP000`）、`MOVJ`・`MOVC`・`MOVS`、`UNTIL`・`NWAIT`・`ENWAIT`・`SPDL=`・`ACC=`・`TOOL#()`、`+MOVJ` の同時移動、PL=1以上・緩い書き方の PL・CR、知らない語はすべて止める（MOVJ を始まりとして認めるかは本人判断待ち。今は止める）
- （仕様v2.1 6章）この位置から出る移動命令（次の移動命令）が上と同じ形でない
- 直前の移動命令が無い、または次の移動命令が無い（入る／出る区間がジョブの中で決まらないため。判断できないものは止める）
- 丸めると値が変わらない

### 累積の基準の扱い
- 基準は「最初に読み込んだ元のジョブの位置の値」。`plan_shift` の `new_job` に引き継ぐので、`new_job` から続けて変更しても基準は元のまま（ジョブ名を変えても引き継ぐ）
- 例：+12mm のあと +12mm は累積 24mm で断る。+12mm のあと −16mm は累積 −4mm で通る
- `parse`・`parse_bytes`・`load` で読み直したジョブは、基準が新しくなる。書き出したファイルをまたいだ基準・枠の引き継ぎ（正規化した中身のハッシュで照合する方式）は、書き出しの設計で扱う
- `Job.baseline` は今は外から書き換えられる。守り方は書き出しの設計で扱う
- **20mm（1回）も累積 20mm も、このアプリが受け付ける量の上限であり、安全の保証ではない**（2026-11-02 に 50mm から 20mm に変更）
- **累積 20mm は暫定措置**：仕様v2.1 の 20mm は「1回の変更上限」。累積の制限は、今後実装する専門家の枠（FRAME）で基準位置から判定する。
  枠ができるまでは、止める側の暫定として累積にも 20mm を使う。FRAME を実装するときに、枠の判定と整合させる（暫定の累積の検査を外すか、枠の範囲と両方を通すかを本人と決める）

### 速度の変更
- **現段階では禁止**（本人の判断）。`plan_speed`（と互換の `set_speed`）は、検査の前に必ず「速度の変更は、単位・指定形式・適用範囲の確認が済むまで、このアプリでは止めています」で断る
- 検査の中身は将来のために残し、`SPEED_CHANGE_ENABLED`（既定 `False`）で切り替える。テストは monkeypatch で `True` にして中身を確かめている
- 中身で断るもの：上の「ジョブ全体を止める」もの、MOVL でない、速度が数値で書かれていない、PL=1以上・緩い書き方の PL・CR・知らない語が付いている、直前・直後の移動命令に PL・CR が付いている（ちょうど ` PL=0` は通す）、新しい速度が bool・数値でない・正の有限数でない・大きすぎて扱えない、整数部の桁が元の値より多くなる（書式が壊れるため。例 `250.0` → `1000.0`）、丸めると値が変わらない・0 になる
- **速度の上限の値は本人の判断待ち**（今は値を決めていない）

### 変更案に入れる注意
- 前後の経路が変わること、検査を通ったことは物理的な安全の保証ではないこと（`PATH_WARNING`）
- ツール番号・ユーザ座標
- 丸めた場合の実際の変化量
- 基準からの累積の変更量（2回目以降の変更のとき）
- 影響する移動（`affected`）：入る区間の始まり（直前の移動命令）・入る移動（対象のMOVL）・出る移動（次の移動命令）
- 速度の単位が設定で変わり得ること（`SPEED_UNIT_WARNING`。速度の変更を有効にしたとき）

### PL=0 の扱い（本人の判断で決定）
- 正本（仕様v2.1 6・7章、CURRENT_DECISIONS 4章）は **PL=0 を通す前提**（「PL=0 で作る・PL>0 を止める」）。CLAUDE.md も「PL>0 を止める」
- 本人（唐川さん）の指示で正本に従い、**ちょうど ` PL=0` と書かれた形だけを通す**（テスト `test_pl0_is_allowed`）
- PL=1以上、`PL=I001`、`PL = 0`、`pl=0`、`PL=0.0`、`PL=00` など緩い書き方は止めたまま。CR は止めたまま
- 経緯：PR #1 修正の原本テストは `test_pl0_is_allowed`、チャッピーの暫定判断でいったん `test_pl0_is_rejected`（PL=0 も拒否）にしたが、修正ラウンド1で原本どおりに戻した

**検査を通ったことは、物理的な安全の保証ではない。** 変更後の経路は、人が確かめてから承認する。
