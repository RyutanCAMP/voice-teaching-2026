# 本物の Claude API を使う（キーを入れたときの準備）

このアプリは、キーが無ければ偽のClaude（モック）で動きます。キーを入れると、発話の解釈だけを本物の Claude に頼みます。
Claude は指示の意味を読むだけです。ジョブの文字列は書きません。結果は必ずプログラムの照らし合わせ（`utterance.check_proposal`）を通り、
変更は人がボタンで承認するまで書き出しません。物理的な安全は保証しません。

## 1. キーを置く

1. `python -m pip install -r requirements.txt`（`anthropic` が入ります。Apache License 2.0）
2. `.env.example` をコピーして、リポジトリ直下に `.env` を作り、キーを書く。
   ```
   ANTHROPIC_API_KEY=（本人のキー）
   # ANTHROPIC_MODEL=claude-opus-5-5   ← 任意。書かなければ claude-opus-5-5
   ```
- `.env` は `.gitignore` で除外しています。**コミットしない・チャットやログに貼らない。**
- `.env` は UTF-8（BOM つきも可）で保存してください。Shift_JIS などで読めないときは、キーが無いものとして扱い
  （モックで動きます）、自己点検で「.env を読めません（UTF-8 で保存してください）」と知らせます。
- `ANTHROPIC_MODEL` は `claude-` で始まり、英小文字・数字・点・ハイフンだけ（`claude-` の後ろは1〜60字）。
  違う書き方のときは送らずに止めます。値は画面・点検に表示しません。
- 環境変数に同じ名前があれば、そちらを使います。
- 会社のPCにキーを置かない方針なら、本人のPCで試してください。

## 2. 自己点検（通信しない）

```
python -m voice_teaching.claude_check
```

表示するもの：`.env` と `ANTHROPIC_API_KEY` が「あり／なし」、使うモデル、SDK を読み込めるか、
例の指示（架空のジョブ `DEMO_PLACE.JBI`、C00004、「この位置をZのプラス10mm移動して」）で送る内容そのもの（キーは伏せる）。
（CHECKER_026 M2 から、上下の向きの設定が無いと「上に10mm」は Claude に送る前に聞き返すため、例は軸と符号を明示した文にした）
キーの中身・長さ・一部は表示しません。キーに全角や空白があれば（見本の文のままなど）知らせます。この状態では送りません。

本物に1回送って確かめるとき（**料金がかかります**。混雑・接続失敗のときは SDK が最大1回やり直します）：

```
python -m voice_teaching.claude_check --call
```

キーが無い・使えない文字・モデル名の書き方が正しくない・`.env` が読めないときは実行しません。
料金の注意を出し、毎回 `yes` と入力したときだけ送ります（入力を省く方法はありません。入力が無ければ送りません）。
画面と同じ流れで照らし合わせまで通し、結果（候補か、止めた理由）だけを表示します。承認・出力はしません。

## 3. 送るもの・送らないもの

送り方は2つあります。どちらも、座標値・//POS の行・ジョブ名・キー・作業ログ・承認者の名前・会社のデータは送りません。

**(a) ふつうの指示の解釈（decide。「この位置を上に10mm」など）**

| 送る | 送らない |
| --- | --- |
| 指示の文（発話） | ジョブの中身（命令の行・座標値・ジョブ名） |
| 選んでいる位置番号（例 C00004） | 作業ログ・承認者の名前 |
| 位置番号の一覧（C00000…） | 会社のデータ |

**(b) 場所の言葉の位置の候補（locate。「置くところを少し手前にして」など。6章。2026-11-03 夜 唐川さんの決定：案A）**

| 送る | 送らない |
| --- | --- |
| 指示の文（発話） | //POS の行・座標値（X・Y・Z・姿勢） |
| 場所の言葉（「置くところ」など、決めた一覧のもの） | ジョブ名（//NAME）・見出し（///DATE など） |
| 位置番号の一覧 | 合成でないジョブの中身（**送らない。Claude を呼ばない**） |
| **命令の行（//INST の部分）とファイルの行番号**（例 `{"line": 30, "text": "MOVL C00005 V=50.0 PL=0"}`） | キー・作業ログ・承認者の名前 |

- (b) は **合成ジョブ（`samples/dummy/` と同じバイト列。`sim._is_synthetic` が真）のときだけ**です。それ以外のジョブでは
  Claude を呼ばず、「このジョブは架空のサンプルではないため、ジョブの中身を Claude に送りません。…位置を選んでください」と出します。
- 承認待ちの変更候補があるときは、(a)(b) とも送りません（呼ぶ前に「承認待ちの変更候補があります…」で止めます）。
- 送る形（`claude_interpreter.build_locate_request`。テスト `tests/test_dialog.py` で固定）：道具は `propose_target`
  （`candidates`：各件 `position`〔一覧からの enum〕・`evidence_lines`〔命令の行番号の enum の並び〕・`rank`〔1〜3〕。
  自由文の項目なし）と `ask_user`。どちらも `strict`・余計な項目は不可。model・max_tokens 8000・effort low・tool_choice auto・
  thinking／temperature などを送らない点は (a) と同じ。

送る形（`claude_interpreter.build_request`。テスト `tests/test_claude_ready.py` で固定）：

- `model`：`claude-opus-5-5`（`ANTHROPIC_MODEL` で変えられる）
- `max_tokens`：8000（考える分も入るため余裕を持たせる）。`output_config.effort`：`low`
- 道具：`propose_position`（位置・方向・量 mm）と `ask_user`。どちらも `strict`、余計な項目は不可
- `tool_choice`：`auto`（並べて呼ばない）。このモデルでは `any`・`tool` は使えない（400）
- 送らない引数：`thinking`、`temperature`、`top_p`、`top_k`（このモデルでは 400）
- 時間切れ 30 秒。1回の指示で送るのは1回（混雑・接続失敗のときは SDK が最大1回やり直します。料金は最大2回分）

応答は、`stop_reason` が `tool_use` で、道具の呼び出しがちょうど1件のときだけ使います（考えた段・文の段は使いません）。
`max_tokens`・`pause_turn`・`end_turn`・`refusal`、2件・0件、知らない道具、余計な項目、数でない・0以下・無限・大きすぎる量、
一覧に無い位置、思わぬ形の応答は、すべて候補を作りません。`ask_user` の Claude の文は使わず、決まった文で聞き返します。

## 4. 失敗したときの表示

モックへは切り替えません。下の文で止め、候補は作りません。キーや生のエラーは画面・ログに出しません。

| 原因 | 表示 |
| --- | --- |
| 401・403（キー・権限）、キーに使えない文字 | Claude に接続できません。APIキーを確認してください（.env の ANTHROPIC_API_KEY） |
| 404（モデル名） | Claude のモデルが見つかりません。モデル名（ANTHROPIC_MODEL）を確認してください |
| モデル名の書き方が正しくない（送る前に止める） | Claude のモデル名（ANTHROPIC_MODEL）の書き方が正しくありません（docs/CLAUDE_API.md を見てください） |
| 429・529・5xx（混雑） | Claude が混み合っています。少し待ってから、もう一度指示してください |
| 接続できない・時間切れ | Claude のネットワークにつながりません。インターネットの接続を確認してください |
| 400・413・422（送り方） | Claude が、送った内容を受け付けませんでした（アプリの送り方の問題かもしれません） |
| Claude が断った（refusal） | Claude がこの指示の解釈を断りました |
| 応答の形がおかしい・その他 | Claude での解釈ができませんでした（接続または応答に問題がありました） |
| `anthropic` が入っていない | Claude の接続を準備できません（anthropic が入っていません） |

画面の上の帯に、今の解釈（「解釈：Claude（モデル名）」か「解釈：モック」）を出します。

## 5. モックに戻す

`.env` の `ANTHROPIC_API_KEY` の行を消す（または `.env` を消す）、環境変数も消してから、起動し直します。
帯が「解釈：モック」になります。失敗したときに自動で戻ることはありません。

## 6. 「置く位置を少し手前に」：実装した（案A が主、案B はつなぎ口だけ）

2026-11-03 夜の唐川さんの決定で作りました（ブランチ `feat/claude-dialog`）。設計は `docs/LOCATE_DESIGN.md`（`docs/frame-prep`）。

目標の会話：
```
人「置くところを少し手前にして」
Claude「「置くところ」は C00005 のことでしょうか？」 ＋根拠（30行目 MOVL C00005 …（C00005 へ直線で動く）／31行目 TIMER T=3.00（待つ）／
        32行目 DOUT OT#(1) OFF（信号を切る））＋［C00005 です］［ほかの位置］。3D で候補の点を光らせる
人「そうそう」                 → C00005 を選ぶ（選択であって承認ではない）。「推定（未確定）」と残す
アプリ「どちらの方向（X・Y・Z の＋−）に、何mm動かしますか？「手前」が X・Y・Z のどれに当たるかは、まだ決まっていません（推測しません）。」
        ＋［X＋］［X−］［Y＋］［Y−］［Z＋（上）］［Z−（下）］
人「3mm」                     → 量だけ分かった。方向は［X＋ 3mm］…［Z−（下）3mm］で聞く
人［Y− 3mm］                  → プログラムが「C00005をYのマイナス3ミリ」を作り、ふつうの指示と同じ流れ（照らし合わせ・
                                 plan_shift・20mm・R1・B1/B6・D1/D2）に通す
アプリ「変更前後を表示します。これでよろしいですか？（承認は確認表示のボタンで行います）」 → 確認表示 → 承認ボタン
```

画面の話し手の表示：Claude（モック）と出すのは、位置の候補を示す文（「「置くところ」は C00005 のことでしょうか？」）だけ。プログラムの決まった文（方向と量の問い・「変更前後を表示します」・照合や手動の選択の案内）は「アプリ」と出す（2026-11-03 夜の決定）。

役割の分け方（変えない）：**Claude＝意図の理解・位置の候補・聞き返し。プログラム＝座標の変更・ガード・数字・承認（ボタンだけ）。**

- 位置の候補（**案A・主**）：合成ジョブの命令の行と行番号を送り（3章 (b)）、Claude は位置番号と根拠の行番号だけを返す。
  プログラム（`dialog.verify_candidates`）が照合：位置がジョブにある／根拠の行が 1〜5件ですべて命令の範囲にある／
  少なくとも1行がその位置を参照する命令か、そのすぐ前・すぐ後／順位が 1〜3 で重ならない／余計な項目が無い。
  通らない候補は捨て、全部捨てたら「…絞り込めませんでした。位置を選んでください」。**1件でも自動では選ばない。**
- 根拠の文はプログラムが行の中身から作る（「待つ」「信号を切る」「信号を入れる」「直線で動く」。DOUT・TIMER の意味
  （つかむ・離す）は断定しない）。Claude の文（`ask_user` の question も）は使わない。
- 推定した名前（「置くところ＝C00005」）はその画面の中だけ。「推定（未確定）」と表示し、保存しない（仕様 v2.1 の19）。
  出力するジョブにも入れない。人が位置を手で選び直すと消える。
- 位置の確認だけは、短い肯定（はい／そう／そうそう／それ／うん／お願いします）を声でも受け付ける。**候補が1つのときだけ**。
  これは位置の選択で、変更の承認ではない。「承認」「OK」「これでいい」などは今どおり断る。打ち消し（「そうじゃなくて」）は止めて、同じ問いのまま。
- 手前・奥・前・後ろ・右・左は軸に当てはめない。方向は6つのボタン（プログラムが作る）か、「Yのマイナス」のような
  はっきりした言葉。量は人の言葉（算用数字＋mm／ミリ）だけ。量のボタンは出さない。
- **案B（補助・つなぎ口だけ）**：FRAME の label・aliases（専門家が review したもの）に一致すれば、Claude を呼ばずにその位置を
  「FRAME の名前（確定）」として出す（`dialog.frame_lookup`）。FRAME はまだ無いので、今は使われない。
- モック（キーが無いとき）：決まった規則（直線移動のすぐ後に DOUT … OFF＝置く側、ON＝取る側）で候補を出す
  （`mock_claude.mock_locate`）。画面に「モック（テスト用）・本物の Claude ではありません」と出す。
- 失敗（通信・断り・思わぬ答え・絞れない・合成でないジョブ）は候補を作らず、決まった短い文で位置の手動の選択へ。
- 会話を始める・続ける条件（内部レビュー 91285fe の FAIL の直し）：場所の言葉を「この位置」に置き換えた文が、ふつうの
  `pre_check` で通るか、会話が受け持つ理由（量が無い・方向が無い・軸だけで向きが無い・あいまいな量だけ）で聞き返されるときだけ。
  ほかの理由（打ち消し・知らない言葉・符号の重なり・D1 の2つの読み方・繰り返し・疑問の形・承認の言葉など）は、そのまま返す。
  場所の言葉が2つ →「位置が2つあります。1つずつ指示してください」。行き先の場所の言葉（「置くところに」）は会話にしない。
  向きの言葉が軸・上げ下げ・符号と一緒、または「置くところの手前」は会話にしない。向きの言葉だけなら、方向は必ず6つのボタンで聞く。
  声の短い肯定は、位置の候補を聞いた直後だけ。手で位置を選んだときは、すぐ候補にせずボタン1つで確かめる。0mm はその場で断る。
  推定（未確定）は、元に戻す・ふつうの指示・候補なしで会話が終わったときに消す。
- 「2回」のような繰り返しは、`utterance.pre_check`（`feat/nl-polish`）が［2回の移動］［2往復］で聞き、どちらでも
  「動きの追加・繰り返しはできません」で止める。会話の層は変えない（解釈の係を呼ばない）。

## 7. やり残し（キーが無いと確かめられないこと）

- 本物の API での疎通・応答の時間・解釈の正しさ（テストは偽の SDK・偽の通信路だけ）。位置の候補（propose_target）を本物の Claude が根拠の行つきで返せるかも、まだ確かめていない
- `max_tokens` 8000・effort low で `stop_reason: max_tokens` にならないか
- サーバー側の `fallbacks`（断られたときに別のモデルで答える仕組み）はこのモデルの系統で使えるが、
  キーで確かめていないので**まだ有効にしていない**。有効にするなら、応答のモデル名の記録と、テストの追加が要る
- 403 がキー以外（組織・地域の制限）のときも「APIキーを確認」と出る

## 8. Claude に聞く（読み取りだけ）：読み込んだ動作を説明してもらう

ブランチ `feat/claude-explain`。`voice_teaching/claude_explain.py`（CLI と画面の「Claude に聞く（読み取りだけ）」の欄）。
**読み取りだけです。** Claude の答えで、ジョブ・変更候補・承認は一切変わりません（このモジュールは Session に触りません。
テスト `tests/test_claude_explain.py` で、聞く前と後の画面の状態が同じことを確かめています）。
動作範囲の特定・回数の変更・検査は、今までどおりプログラムが行います。レビュー済みの変更エンジンにつなぐのは、あとの段階です。

目標の会話（実際の出力を見て台本を直す）：
```
人「このロボット、何をしている？」
Claude「Z方向の往復動作が2回あります。ボタンを押す動作として設定されていますか？」＋根拠の行（21〜26行目）
人「そう。じゃあ3回にして」
Claude「この動作を3回に変更しますか？」
アプリ「変更は、プログラムの確認（範囲のボタン）と承認ボタンを通して行います。今は読み取りの確認だけです」
```
（上下の向きが未確認のあいだは「上下」と言わせず「Z方向」と言わせます。下の検査も参照）

### 8-1. キーの設定（本人がする）

1. `C:\アプリ\voice-teaching\.env` に次を書く（`.env` は `.gitignore` 済み。コミットしない・チャットやログに貼らない）。
   ```
   ANTHROPIC_API_KEY=（本人のキー）
   ANTHROPIC_MODEL=claude-sonnet-5-5
   ```
2. worktree（別のフォルダ）から使うときは、`--env-file C:/アプリ/voice-teaching/.env` で本体の `.env` を指定する
   （CLI・`python -m voice_teaching.web` の両方）。環境変数に同じ名前があれば、そちらを使います。
- キーは画面・ログ・`records/api_usage.jsonl`・エラーの文に出しません（先頭の数文字も出しません）。画面（ブラウザー）にも送りません。
- 注意：`ANTHROPIC_API_KEY` があると、ふつうの指示の解釈（3章）も本物の Claude になります（今までどおり）。
  `ANTHROPIC_MODEL` も両方に効きます。

### 8-2. モデル名の変え方

- 既定は `claude-sonnet-5-5`（`ANTHROPIC_MODEL` が無いとき）。`ANTHROPIC_MODEL` か、起動オプション
  （CLI は `--model`、画面は `python -m voice_teaching.web --explain-model ...`）で変えます。オプションが一番強い。
- 書き方の検査は3章と同じ（`claude-` で始まる英小文字・数字・点・ハイフン）。
- **料金の表（`PRICES`）に無いモデルは呼びません**（料金不明で、上限を確かめられないため）。表にあるのは
  `claude-sonnet-5-5` と `claude-opus-5-5` だけです（claude-api の shared/models.md・model-migration.md で確かめた値）。

### 8-3. 送るもの・送らないもの（合成ジョブだけ）

合成ジョブ（`samples/dummy/` と同じバイト列。`sim._is_synthetic`）のときだけ送ります。それ以外のジョブでは Claude を呼びません
（「このジョブは架空のサンプルではないため、ジョブの中身を Claude に送りません」）。

| 送る（プログラムが作る） | 送らない |
| --- | --- |
| 命令の行（//INST の部分）とファイルの行番号 | //POS の行・座標の値（X・Y・Z・姿勢） |
| 位置番号の一覧 | ジョブ名（//NAME）・見出し（///DATE など）・コメントの行 |
| 動きの要約：区間ごとの始点→終点・命令の種類（MOVL/MOVJ）・軸ごとの変化量 mm（プログラムが計算した差） | キー・作業ログ・承認者の名前・会社のデータ |
| 繰り返しの区間（`jbi.Job.find_repeat` で数えたもの。例：C00001〜C00003 が 21〜26行目に2回） | 合成でないジョブの中身 |
| 上下の向きの状態（確認済みか、未確認＝「Z方向とだけ言う」） | |
| 聞く文（人が言った・書いた文） | |

送る形（`build_request`）：`model`・`max_tokens` 3000（考える分も入る）・`output_config.effort` `low`・
`cache_control`（自動のキャッシュ、5分）・道具 `answer`（`strict`、余計な項目は不可）・`tool_choice` `auto`
（Sonnet 5.5 では `any`・`tool` は 400）・`thinking`／`temperature` などは送らない（Sonnet 5.5 では `disabled` は 400）。
時間切れ 30 秒、SDK のやり直しは最大1回。`--call` なしの CLI で、送る内容をそのまま見られます。

道具 `answer` の項目：`reply`（短い日本語の文）、`evidence_lines`（根拠の命令の行番号の配列）、
`intent`（`explain`｜`ask_user`｜`change_request`｜`other`）、`change_request`
（`{kind:"repeat", from_count, to_count}`｜`{kind:"shift"}`｜`null`。**記録と表示だけで、何も変えません**）。

### 8-4. プログラムの検査（Claude の文をそのまま信じない）

- 道具を呼ばずに文だけ返した・`stop_reason` が `tool_use` でない・2件・知らない道具・余計な項目・形の違う change_request
  → 文を捨てて「Claude の答えを読めませんでした」（断った `refusal`、途中で切れた `max_tokens` はそれぞれの文）。
- 根拠の行は、命令の行の範囲にあるものだけ使う（無い行・コメントの行は捨てる）。行の中身はプログラムがジョブから入れる。
- 次のどれかがあれば、Claude の文は表示せず、決まった文にする：
  安全や距離を決めつける言葉（`utterance.FORBIDDEN_WORDS` と、安全・干渉・衝突・当たる など）／
  送った事実と人の文に無い数／上下の向きが未確認なのに「上」「下」（「以上」「以下」「下さい」などは除く）／
  命令の行のような文字列（`MOVL C00002`・`V=30.0` など）／変えたような言い方（「変更しました」など）／長すぎる文。
  表示しなかったことは、次の要求の `tool_result` で Claude に伝えます（アプリが作る決まった文）。
- intent が change_request のときは、Claude の文の後に、アプリの決まった文
  「変更は、プログラムの確認（範囲のボタン）と承認ボタンを通して行います。今は読み取りの確認だけです」を出します。
- 自動では聞き直しません（同じ質問を勝手に送り直さない）。

### 8-5. 会話の文脈

- 同じ画面（CLI の1回の実行）のメモリの中だけで持ちます。ファイルに保存しません。
- 前の assistant の返事（考える分のブロックを含む content）は、**書き換えずにそのまま**次の要求に入れます。
  事実は最初のメッセージだけに入れ、system と tools は会話の間で変えません（Sonnet 5.5 の preserved thinking の決まり）。
  前の答えへの `tool_result` は、次の人の文の前に置きます。
- 古い往復を消すと書き換えになるので、1つの会話は **6回** まで。超えたら「会話をやり直す」で始め直します。
- ジョブか上下の向きの照合の結果が変わったら、新しい会話にします。

### 8-6. 料金の見方と上限

- 返事の `usage`（input・output・キャッシュの書き込み・読み）から、値段の表で推定料金を計算します。
  `claude-sonnet-5-5`：入力 $2・出力 $10・キャッシュ読み $0.20・キャッシュ書き込み $2.50（5分）/ 100万トークン
  （考える分は出力に入ります）。`claude-opus-5-5`：入力 $4・出力 $20・読み $0.20・書き込み $5（5分）。
  **推定です。** 正しい請求は Anthropic の Console で確かめてください。
- 1回ごとに `records/api_usage.jsonl`（`.gitignore` 済み）に1行足します：日時・モデル・トークン数・推定料金だけ
  （送った中身・答えの文・キーは書きません）。この合計が累計です。`usage` が無い返事は、最大の見積もりで記録します。
- **上限**：累計＋この1回の最大の見積もり（送る文字数をトークン数の上限の目安にし、出力は max_tokens 分）が、
  上限（既定 **$5**。環境変数 `VOICE_TEACHING_API_BUDGET_USD`、例 `VOICE_TEACHING_API_BUDGET_USD=1`）を超えるなら呼びません。
  上限の値が読めない・記録が読めない・記録に書けなかったときも、呼びません（止める側）。
- 画面の欄には、このセッションのトークン数・推定料金・累計・上限を小さく出します。CLI は各回に出します。

### 8-7. 使い方

CLI（最初の確認用。ふだんは通信しない）：
```
python -m voice_teaching.claude_explain --job samples/dummy/DEMO_BUTTON_REPEAT.JBI \
    --say "このロボット、何をしている？" --say "そう。じゃあ3回にして" \
    [--model claude-sonnet-5-5] [--env-file C:/アプリ/voice-teaching/.env]
```
- `--call` が無ければ、送る内容（システムの文・事実の要約・道具）を表示するだけです（キーは要りません）。
- `--call` を付けると、キー・モデル名・料金の表・上限を確かめたあと、料金の注意を出し、`yes` と入力したときだけ送ります
  （入力を省く方法はありません）。各回に Claude の文・根拠の行（行の中身つき）・intent・change_request・トークン数・
  推定料金・累計を出します。失敗したら、残りの文は送りません。

画面：`python -m voice_teaching.web [--env-file ...] [--explain-model ...]` で起動し、ジョブを読み込むと、図の下に
「Claude に聞く（読み取りだけ）」の欄が出ます。
- `POST /api/ask`：`{session_id, text}` で聞く（返事は reply・根拠の行・intent・change_request・使用量）。
  `{session_id, info: true}` はキーの有無・モデル・累計だけ、`{session_id, reset: true}` は会話をやり直す。
- キーが無いときは「APIキーが設定されていません」と出し、モックでは答えません（ふつうの指示のモックの説明と混同させない）。
- 「🎤 で聞き取った文を、この欄に入れる」に印を付けると、マイクの結果がこの欄に入ります（自動では送りません）。
- 根拠の行を押すと、その行の位置を 3D の図で光らせます（選択ではありません）。

### 8-8. やり残し

- 本物の API でまだ一度も呼んでいません（テストは偽の client だけ）。`strict` の道具の形（`anyOf` の null・整数の enum）を
  本物が受け付けるか、`max_tokens` 3000・effort low で切れないか、答えの文が検査に通る割合は、キーを入れてから確かめます。
- 数の検査は「送った事実と人の文にある数か」だけです。数の意味（どの区間の数か）までは確かめません。
- 根拠の行が答えの内容に合っているかは、プログラムでは確かめていません（範囲の中かどうかだけ）。
- 推定料金は表の値での計算です。料金が変わったら `PRICES` を直してください。

### 8-9. 会話を自然にする（CHECKER_031 E1〜E7・台本 Ver.6.1 Scene 3。`voice_teaching/claude_talk.py`）

- **E1 やさしい言葉**：最初の答えに位置番号・命令の名前・「ジョブ」があれば、作り直しを頼まず、プログラムが事実から作る文
  （「同じ動きを2回くり返しています。何をする動きか、教えてもらえますか？」）にする。「？」が2つ以上の答えは使わない。
  番号と命令は、根拠の行からプログラムが作る「補足」に出す。上下は今の照合の結果のまま（確認済みなら「下りて戻る」も通す）。
- **位置の役割**（待機の位置・作業の場所など）はプログラムが知らない事実なので、Claude の文にあれば「AI の推定（未確定）」の印を付ける（文は書き換えない）。
- **E2 人が教えた意味**：登録はプログラムが人の文と事実で決める。相づちだけ・ためらい・打ち消し・対象が1つに決まらない・
  事実と合わない（区間に無い位置）・安全や距離の言葉、では登録しない。「〜じゃなくて〜」は前の意味の訂正。区間が決まらなければ
  「どの動きのことですか？」とボタンで選ぶ（声・文字では選ばない）。Claude の道具の項目は増やしていない（Claude には登録させない）。
  画面のメモリの中だけ（ファイル・records/・作業ログ・ブラウザーの保存に書かない）。同じ中身（`normalized_hash`）の読み直しは
  引き継ぎ（画面が `X-VT-Previous-Session` で前の画面の番号を渡す）、別のデータでは消す。候補・承認・元に戻すで状態が変わったら
  対応を確かめ直し、確かめられなければ無効にして「さきほど教えてもらった意味（…）を確認できなくなりました。もう一度教えてください」。
  「会話をやり直す」でも消す。`/api/hear` の流れは意味を読まない（変更してよい範囲・上限・承認は同じ）。
- **E4**：返事のたびに、根拠の行番号からプログラムが決めた範囲（くり返しの区間に入る行なら区間の全部）を 3D で光らせる。MOVJ は点線のまま。
- **E5**：承認待ちの候補があるときは、変更の希望のような文を Claude に送らない（説明だけ）。回数はプログラムが人の文から読み、
  Claude の数と違えば「食い違い」（候補は作らない）。打ち消し・ためらいのある回数は読まない・送らない。「全部」と区間が2つ以上なら対象を決めない。
  データが変わったら**会話を区切る**（新しい会話にして「データが変わったので、ここからは新しい内容で答えます」）。
  `change_record` に、あとで変更エンジンへつなぐための事実（読んだ回数・区間・根拠の行が区間に収まるか）を出す（このブランチでは記録だけ）。
- `/api/ask` の追加：`source`（voice・text。同じ検査）、`sync: true`（確かめ直しと知らせだけ）、`choose`・`token`（区間のボタン）。
