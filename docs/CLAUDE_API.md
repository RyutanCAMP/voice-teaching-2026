# 本物の Claude API を使う（キーを入れたときの準備）

このアプリは、キーが無ければ偽のClaude（モック）で動きます。キーを入れると、発話の解釈だけを本物の Claude に頼みます。
Claude は指示の意味を読むだけです。ジョブの文字列は書きません。結果は必ずプログラムの照らし合わせ（`utterance.check_proposal`）を通り、
変更は人がボタンで承認するまで書き出しません。物理的な安全は保証しません。

## 1. キーを置く

1. `python -m pip install -r requirements.txt`（`anthropic` が入ります。Apache License 2.0）
2. `.env.example` をコピーして、リポジトリ直下に `.env` を作り、キーを書く。
   ```
   ANTHROPIC_API_KEY=（本人のキー）
   # ANTHROPIC_MODEL=claude-opus-5-5   ← 任意。書かなければ claude-opus-5-5
   ```
- `.env` は `.gitignore` で除外しています。**コミットしない・チャットやログに貼らない。**
- `.env` は UTF-8（BOM つきも可）で保存してください。Shift_JIS などで読めないときは、キーが無いものとして扱い
  （モックで動きます）、自己点検で「.env を読めません（UTF-8 で保存してください）」と知らせます。
- `ANTHROPIC_MODEL` は `claude-` で始まり、英小文字・数字・点・ハイフンだけ（`claude-` の後ろは1〜60字）。
  違う書き方のときは送らずに止めます。値は画面・点検に表示しません。
- 環境変数に同じ名前があれば、そちらを使います。
- 会社のPCにキーを置かない方針なら、本人のPCで試してください。

## 2. 自己点検（通信しない）

```
python -m voice_teaching.claude_check
```

表示するもの：`.env` と `ANTHROPIC_API_KEY` が「あり／なし」、使うモデル、SDK を読み込めるか、
例の指示（架空のジョブ `DEMO_PLACE.JBI`、C00004、「この位置を上に10mm移動して」）で送る内容そのもの（キーは伏せる）。
キーの中身・長さ・一部は表示しません。キーに全角や空白があれば（見本の文のままなど）知らせます。この状態では送りません。

本物に1回送って確かめるとき（**料金がかかります**。混雑・接続失敗のときは SDK が最大1回やり直します）：

```
python -m voice_teaching.claude_check --call
```

キーが無い・使えない文字・モデル名の書き方が正しくない・`.env` が読めないときは実行しません。
料金の注意を出し、毎回 `yes` と入力したときだけ送ります（入力を省く方法はありません。入力が無ければ送りません）。
画面と同じ流れで照らし合わせまで通し、結果（候補か、止めた理由）だけを表示します。承認・出力はしません。

## 3. 送るもの・送らないもの

送り方は2つあります。どちらも、座標値・//POS の行・ジョブ名・キー・作業ログ・承認者の名前・会社のデータは送りません。

**(a) ふつうの指示の解釈（decide。「この位置を上に10mm」など）**

| 送る | 送らない |
| --- | --- |
| 指示の文（発話） | ジョブの中身（命令の行・座標値・ジョブ名） |
| 選んでいる位置番号（例 C00004） | 作業ログ・承認者の名前 |
| 位置番号の一覧（C00000…） | 会社のデータ |

**(b) 場所の言葉の位置の候補（locate。「置くところを少し手前にして」など。6章。2026-11-03 夜 唐川さんの決定：案A）**

| 送る | 送らない |
| --- | --- |
| 指示の文（発話） | //POS の行・座標値（X・Y・Z・姿勢） |
| 場所の言葉（「置くところ」など、決めた一覧のもの） | ジョブ名（//NAME）・見出し（///DATE など） |
| 位置番号の一覧 | 合成でないジョブの中身（**送らない。Claude を呼ばない**） |
| **命令の行（//INST の部分）とファイルの行番号**（例 `{"line": 30, "text": "MOVL C00005 V=50.0 PL=0"}`） | キー・作業ログ・承認者の名前 |

- (b) は **合成ジョブ（`samples/dummy/` と同じバイト列。`sim._is_synthetic` が真）のときだけ**です。それ以外のジョブでは
  Claude を呼ばず、「このジョブは架空のサンプルではないため、ジョブの中身を Claude に送りません。…位置を選んでください」と出します。
- 承認待ちの変更候補があるときは、(a)(b) とも送りません（呼ぶ前に「承認待ちの変更候補があります…」で止めます）。
- 送る形（`claude_interpreter.build_locate_request`。テスト `tests/test_dialog.py` で固定）：道具は `propose_target`
  （`candidates`：各件 `position`〔一覧からの enum〕・`evidence_lines`〔命令の行番号の enum の並び〕・`rank`〔1〜3〕。
  自由文の項目なし）と `ask_user`。どちらも `strict`・余計な項目は不可。model・max_tokens 8000・effort low・tool_choice auto・
  thinking／temperature などを送らない点は (a) と同じ。

送る形（`claude_interpreter.build_request`。テスト `tests/test_claude_ready.py` で固定）：

- `model`：`claude-opus-5-5`（`ANTHROPIC_MODEL` で変えられる）
- `max_tokens`：8000（考える分も入るため余裕を持たせる）。`output_config.effort`：`low`
- 道具：`propose_position`（位置・方向・量 mm）と `ask_user`。どちらも `strict`、余計な項目は不可
- `tool_choice`：`auto`（並べて呼ばない）。このモデルでは `any`・`tool` は使えない（400）
- 送らない引数：`thinking`、`temperature`、`top_p`、`top_k`（このモデルでは 400）
- 時間切れ 30 秒。1回の指示で送るのは1回（混雑・接続失敗のときは SDK が最大1回やり直します。料金は最大2回分）

応答は、`stop_reason` が `tool_use` で、道具の呼び出しがちょうど1件のときだけ使います（考えた段・文の段は使いません）。
`max_tokens`・`pause_turn`・`end_turn`・`refusal`、2件・0件、知らない道具、余計な項目、数でない・0以下・無限・大きすぎる量、
一覧に無い位置、思わぬ形の応答は、すべて候補を作りません。`ask_user` の Claude の文は使わず、決まった文で聞き返します。

## 4. 失敗したときの表示

モックへは切り替えません。下の文で止め、候補は作りません。キーや生のエラーは画面・ログに出しません。

| 原因 | 表示 |
| --- | --- |
| 401・403（キー・権限）、キーに使えない文字 | Claude に接続できません。APIキーを確認してください（.env の ANTHROPIC_API_KEY） |
| 404（モデル名） | Claude のモデルが見つかりません。モデル名（ANTHROPIC_MODEL）を確認してください |
| モデル名の書き方が正しくない（送る前に止める） | Claude のモデル名（ANTHROPIC_MODEL）の書き方が正しくありません（docs/CLAUDE_API.md を見てください） |
| 429・529・5xx（混雑） | Claude が混み合っています。少し待ってから、もう一度指示してください |
| 接続できない・時間切れ | Claude のネットワークにつながりません。インターネットの接続を確認してください |
| 400・413・422（送り方） | Claude が、送った内容を受け付けませんでした（アプリの送り方の問題かもしれません） |
| Claude が断った（refusal） | Claude がこの指示の解釈を断りました |
| 応答の形がおかしい・その他 | Claude での解釈ができませんでした（接続または応答に問題がありました） |
| `anthropic` が入っていない | Claude の接続を準備できません（anthropic が入っていません） |

画面の上の帯に、今の解釈（「解釈：Claude（モデル名）」か「解釈：モック」）を出します。

## 5. モックに戻す

`.env` の `ANTHROPIC_API_KEY` の行を消す（または `.env` を消す）、環境変数も消してから、起動し直します。
帯が「解釈：モック」になります。失敗したときに自動で戻ることはありません。

## 6. 「置く位置を少し手前に」：実装した（案A が主、案B はつなぎ口だけ）

2026-11-03 夜の唐川さんの決定で作りました（ブランチ `feat/claude-dialog`）。設計は `docs/LOCATE_DESIGN.md`（`docs/frame-prep`）。

目標の会話：
```
人「置くところを少し手前にして」
Claude「「置くところ」は C00005 のことでしょうか？」 ＋根拠（30行目 MOVL C00005 …（C00005 へ直線で動く）／31行目 TIMER T=3.00（待つ）／
        32行目 DOUT OT#(1) OFF（信号を切る））＋［C00005 です］［ほかの位置］。3D で候補の点を光らせる
人「そうそう」                 → C00005 を選ぶ（選択であって承認ではない）。「推定（未確定）」と残す
Claude「どちらの方向（X・Y・Z の＋−）に、何mm動かしますか？「手前」が X・Y・Z のどれに当たるかは、まだ決まっていません（推測しません）。」
        ＋［X＋］［X−］［Y＋］［Y−］［Z＋（上）］［Z−（下）］
人「3mm」                     → 量だけ分かった。方向は［X＋ 3mm］…［Z−（下）3mm］で聞く
人［Y− 3mm］                  → プログラムが「C00005をYのマイナス3ミリ」を作り、ふつうの指示と同じ流れ（照らし合わせ・
                                 plan_shift・20mm・R1・B1/B6・D1/D2）に通す
Claude「変更前後を表示します。これでよろしいですか？（承認は確認表示のボタンで行います）」 → 確認表示 → 承認ボタン
```

役割の分け方（変えない）：**Claude＝意図の理解・位置の候補・聞き返し。プログラム＝座標の変更・ガード・数字・承認（ボタンだけ）。**

- 位置の候補（**案A・主**）：合成ジョブの命令の行と行番号を送り（3章 (b)）、Claude は位置番号と根拠の行番号だけを返す。
  プログラム（`dialog.verify_candidates`）が照合：位置がジョブにある／根拠の行が 1〜5件ですべて命令の範囲にある／
  少なくとも1行がその位置を参照する命令か、そのすぐ前・すぐ後／順位が 1〜3 で重ならない／余計な項目が無い。
  通らない候補は捨て、全部捨てたら「…絞り込めませんでした。位置を選んでください」。**1件でも自動では選ばない。**
- 根拠の文はプログラムが行の中身から作る（「待つ」「信号を切る」「信号を入れる」「直線で動く」。DOUT・TIMER の意味
  （つかむ・離す）は断定しない）。Claude の文（`ask_user` の question も）は使わない。
- 推定した名前（「置くところ＝C00005」）はその画面の中だけ。「推定（未確定）」と表示し、保存しない（仕様 v2.1 の19）。
  出力するジョブにも入れない。人が位置を手で選び直すと消える。
- 位置の確認だけは、短い肯定（はい／そう／そうそう／それ／うん／お願いします）を声でも受け付ける。**候補が1つのときだけ**。
  これは位置の選択で、変更の承認ではない。「承認」「OK」「これでいい」などは今どおり断る。打ち消し（「そうじゃなくて」）は止めて、同じ問いのまま。
- 手前・奥・前・後ろ・右・左は軸に当てはめない。方向は6つのボタン（プログラムが作る）か、「Yのマイナス」のような
  はっきりした言葉。量は人の言葉（算用数字＋mm／ミリ）だけ。量のボタンは出さない。
- **案B（補助・つなぎ口だけ）**：FRAME の label・aliases（専門家が review したもの）に一致すれば、Claude を呼ばずにその位置を
  「FRAME の名前（確定）」として出す（`dialog.frame_lookup`）。FRAME はまだ無いので、今は使われない。
- モック（キーが無いとき）：決まった規則（直線移動のすぐ後に DOUT … OFF＝置く側、ON＝取る側）で候補を出す
  （`mock_claude.mock_locate`）。画面に「モック（テスト用）・本物の Claude ではありません」と出す。
- 失敗（通信・断り・思わぬ答え・絞れない・合成でないジョブ）は候補を作らず、決まった短い文で位置の手動の選択へ。
- 「2回」のような繰り返しは、`utterance.pre_check`（`feat/nl-polish`）が［2回の移動］［2往復］で聞き、どちらでも
  「動きの追加・繰り返しはできません」で止める。会話の層は変えない（解釈の係を呼ばない）。

## 7. やり残し（キーが無いと確かめられないこと）

- 本物の API での疎通・応答の時間・解釈の正しさ（テストは偽の SDK・偽の通信路だけ）。位置の候補（propose_target）を本物の Claude が根拠の行つきで返せるかも、まだ確かめていない
- `max_tokens` 8000・effort low で `stop_reason: max_tokens` にならないか
- サーバー側の `fallbacks`（断られたときに別のモデルで答える仕組み）はこのモデルの系統で使えるが、
  キーで確かめていないので**まだ有効にしていない**。有効にするなら、応答のモデル名の記録と、テストの追加が要る
- 403 がキー以外（組織・地域の制限）のときも「APIキーを確認」と出る
