# 作業の回数を変える（2回 → 3回）の設計メモ

唐川さんの依頼（2026-11-03）：「既存の作業を2回から3回に変更する」を、PC 上のシミュレーションで動くところまで作る。
3分デモの中心にする機能。ブランチ `feat/repeat-count`（土台 f783b2f）。安全修正のブランチには混ぜない。

**検査を通ったことは、物理的な安全の保証ではない。** このアプリはロボットを動かさない・転送しない。出力は合成ジョブだけ。

## 0. 唐川さんの決定（2026-11-03。内部レビューのあと）
- **繰り返す範囲を、人がボタンで確定する**（CHECKER_029B 2-2 の案）。指示を受けると、プログラムが範囲を見つけて
  見出し「この範囲を繰り返しますか？」の下に「1回目：21〜23行目（MOVL C00001 V=150.0・…）／2回目：24〜26行目／全体：21〜26行目（2回）」と
  「今は2回続けて書かれています。合計3回にします」を出し（範囲は大きく、対象外の文は下に小さく。確認表示の文にも同じ範囲を入れる）、
  ［この範囲を繰り返す］［違う］のボタンを出す（行番号・命令の行・回数はプログラムが入れる）。3D でその範囲の点と線を光らせる。
  ［この範囲を繰り返す］を押して初めて候補を作る（`Session.confirm_repeat`）。声の「はい」「そうそう」では確定しない。［違う］は何もしない。
  範囲を確かめている間に、別の指示・位置の選び直し・元に戻す・ほかのボタンがあれば、範囲の確認を捨てる（古いボタンは番号 turn が合わず、候補にならない）。
- つなぎの移動と DOUT・TIMER は、今の厳しい制限のまま。
- **減らす変更（3 → 2、2 → 1）は止める**（「減らす変更は、このプロトタイプでは扱いません」）。減らす選択肢も出さない。
- **誤解させない表示**：繰り返すのは移動の行だけです。信号（DOUT）や待ち時間（TIMER）を含む作業は、このプロトタイプでは対象外です。確認表示・候補のカード・範囲の確認・ジョブを調べて止まったときの文に、この固定文を出す。
- 範囲を言わない言い方（「3回にして」「2回から3回」「もう1回ふやして」）は、ジョブに数えられる区間がちょうど1つのとき、その区間で範囲の確認へ進む。
  区間が無い・2つ以上のときは「回数を変えるときは『C00001からC00003の作業を2回から3回にして』のように、範囲を言ってください」と案内する。
- 短い位置の名前（C1・C001 → C00001）・漢数字の一〜五・かなの回数（さんかい・3かい）も読む（範囲はボタンで人が確定する）。小数の回数は止める。
- 聞き返しの選択肢は、押せば候補（範囲の確認）に進むもの・増やす向きのものだけ。どう答えても止まるときは、聞き返さずに理由を出して止める。

## 1. 今までの決まりを、どこだけ変えるか
- CHECKER_025（統合前の確認 part1）5章②「命令を足すことはしない」を、**下の条件に限って**変える（唐川さんの依頼）。
- それ以外の決まり（位置の変更の検査・速度の変更を止める・承認はボタンだけ・出力は合成ジョブだけ・ロボットを動かさない）は変えない。
- 任意のジョブを自由に直す汎用の機能にはしない。「区間がジョブの中に続けてそのまま N 回書かれている」形だけを扱う。

## 2. 繰り返しの表し方（何を「N 回」と数えるか）
- JUMP・ラベル・カウンタ（I 変数）の繰り返しは扱わない（ジョブに JUMP・CALL・RET・ラベル行が1つでもあれば止める）。
- 区間（1サイクル）が、ジョブの中に**間をあけずに**そのまま N 回並んでいる形だけを「N 回」と数える。

### 区間の条件（`jbi.Job.find_repeat`）
- 「C00001からC00003」＝ C00001・C00002・C00003（番号の続いた位置）を行き先にする移動命令が、その順で続く並び。
  始まりの番号が終わりの番号より小さいこと。区間の位置はすべてジョブにあり、ロボット座標（ROBOT・RECTAN・値6個）であること。
- 区間の位置を使う命令は、すべて PL なし（またはちょうど ` PL=0`）の `MOVL 位置 V=数値` だけ。
- 区間の位置を使う最初の行から最後の行までのあいだ（区間の中と、区間と区間の間）に、ほかの行があれば止める：
  DOUT・WAIT・TIMER・MOVJ・コメント・区間の外の位置への移動・ほかの命令（理由の文「区間の中に DOUT があるため、複写しません（n行目「…」）」）。
  PL=1 以上・CR・別の速度・知らない語の付いた行も止める。
- その範囲が、区間の並び（C00001→C00002→C00003）のちょうど N 回の繰り返しで、各回の行がバイト列として同じ（速度・PL=0 の有無・改行コードも同じ）。
  範囲が区間の位置を使う行の全部なので、N 回の前と後ろの命令は区間の並びと同じではない。
- ジョブ全体を止めるもの（`problems`。読めない行・知らない命令・WAIT など許可リストに無い命令・END が無い など）があれば止める。
  位置の意味を変える命令（SFTON・MSHIFT など）があっても止める。

### 変えてよい回数（`jbi.Job.plan_repeat`）
- **今が2回以上のときだけ**変える。区間と区間のつなぎの移動（最後の位置 → 最初の位置）がもうジョブの中にあるため、
  1回分を足しても新しい移動の線はできない。1回 → 2回は新しい移動の線ができるので止める。
- **このプロトタイプでは、今が2回の区間を合計3回にする変更だけを扱う**（CURRENT_DECISIONS 73行目・11/3 16:21。`jbi.REPEAT_FROM`・`REPEAT_TO`）。
  ほか（3 → 4、4 → 5、2 → 4 など）は「このプロトタイプでは、2回から3回への変更だけを扱います」で止める。
  今と同じ回数・減らす変更もそれぞれの理由で止める。どう答えても止まるので、聞き返さない。
  考え方として、将来ほかの回数を扱うときは、専門家の枠で上限を決める（今は決めていない）。
- 最後の回の直後に、1回分の行（1回目と同じバイト列）を足す。減らす変更は扱わない（唐川さんの決定）。
- 変えるのは INST 部の命令の行の並びだけ。//POS の位置の値・ヘッダー・ほかの行は変えない。新しい位置は作らない。
- 変更後のジョブを読み直し、①problems が無い ②区間が同じ並び・同じ行で、ちょうど変更後の回数 ③足した（消した）所のほかの行が元と同じ
  ④//INST より前（ヘッダー・POS 部）が元と同じ、を確かめる。合わなければ止める。
- 元のジョブ（Job・元のバイト列）は変えない。変更は `RepeatProposal.new_job` の中だけ。

### つなぎの移動を暗黙に作らない（唐川さんの追加の指示 2026-11-03）
- 移動の区間＝「直前の移動の行き先 → この移動の命令の行（命令の種類・行き先・速度・PL を含む）」（`jbi.move_segments`）。
- 変更後のジョブの移動の区間が、**すべて変更前のジョブの区間の集まりの中にある**ことをプログラムで確かめる（`jbi.new_move_segments`）。
  区間の数は増えてよいが、今までに無い組が1つでもあれば候補を作らず、
  「C00003 から C00001 への移動（「MOVL C00001 V=150.0」）が、今のジョブにありません。新しい移動を作るため、回数は変えません」と出す。
  上の区間の条件（続けてそのまま N 回、N≥2）を通れば、つなぎの移動はもうジョブにあるので、この検査は独立の二重の確かめになる
  （テストでは、区間の数え方を通っても新しい組があれば止まることを、わざと組を足して確かめている）。
- 1回目に入る移動（例 `MOVJ C00000` → `MOVL C00001`）と、最後の回のあとの移動（`MOVL C00003` → `MOVJ C00004`）が、
  命令の行と直前の行き先ごと変わらないことも確かめる。
- 複写したあとの区間の中の移動と、その始点の移動が、`MOVL 位置 V=数値`（PL なし／ちょうど PL=0）であることも、変更後のジョブで確かめ直す
  （plan_shift の「入る区間・出る区間」と同じ考え方）。1回目に入る移動の始点（MOVJ）は、変わらないことだけを確かめる（MOVJ を変える・複写することはしない）。
- 確認表示の注意に、プログラムが確かめた事実として「新しい移動の区間はありません（変更のあとも、今のジョブにある 6 種類の移動の区間だけです。プログラムで確かめました）」を出す（数はプログラムが入れる）。

## 3. 言葉の読み取り（`voice_teaching/repeat_count.py`。Claude には頼まない）
- 対象の発話：位置の範囲（`C00001からC00003`・`C00001〜C00003`・`C00001~C00003`）と、回数の変更の言葉
  （`N回から`・`N回に`・`N回へ`・`N回追加`・`N回ふやし`・`N回増やし`・`N回足し`）がある発話。
  これに当たらない「2回移動させて」などは、今どおり（繰り返し・往復の2択で聞いて止める）。
- 決まった形だけを読む：`<範囲>（まで）（の作業／の区間）を（N回から）M回に（して／変更して／変えて）（ください）`。
  前置きの「えーと」「それでは」なども今の一覧の言葉だけ。形に合わない言葉があれば、その言葉を示して聞き返す（B1 と同じく、言葉を捨てて読まない）。
- 先にかける検査（今のまま）：打ち消し（「3回にしないで」）→ 止める。承認・起動の言葉 → 止める。疑問の形 → 確かめる（候補にしない）。
- 位置の移動（mm）・速度・選択・比較・元に戻すの言葉が同じ発話にあれば止める（1回に1つの変更）。
- 「3回追加して」「1回ふやして」は合計か追加かが曖昧なので、ジョブの今の回数を示して聞き返す。選択肢は、押せば範囲の確認に進むもの
  （今2回なら合計3回になるもの）だけ（［合計3回にする］または［1回足して合計3回にする］）。1つも無ければ止める。
  押すと、今の回数を入れた決まった文（`C00001からC00003の作業を2回から3回にして`）を指示として送る（同じ検査を通る）。
- 言った「今の回数」がジョブと違うとき：言った目標が3回なら、今の回数を示して［合計3回にする］の1択で聞く。
  言った目標が3回でなければ、言った目標と違う回数は選択肢に出さず、止める（「1回から2回」「5回から6回」など）。
- 今の回数を言わないとき（「3回にして」）は、範囲の確認のボタンで今の回数と範囲を示して確かめる（別の聞き返しはしない）。
- 承認待ちの候補があれば、今どおり断る（承認待ちの文）。

## 4. 候補・承認・出力
- Session の候補に、新しい種類「回数の変更」（`kind="repeat"`、`jbi.RepeatProposal`）を足す。今の位置の移動の候補（`ChangeProposal`）は変えない。
- 回数の変更は、解釈の係（Claude／モック）を呼ばずに、プログラムが候補まで作る（`Session.hear` が `candidate_made=True` で返す）。
  その発話では、ほかの提案を受け付けない（今どおり1つの発話で1つの候補）。
- 承認は画面のボタンだけ（`WebFlow.approve`）。声の「はい」「承認」では承認しない（今どおり止める）。
  承認のとき、元のジョブから同じ候補を作り直して、バイト列が同じときだけ承認する（`sim.simulate_repeat`）。
- 承認後の新しい指示・元に戻す・位置の選び直しで、承認を消す（今の仕組みのまま）。
- 出力は今どおり合成ジョブ（`samples/dummy/*.JBI` とバイト単位で一致するもの）から作った候補だけ。名前は `<ジョブ名>_SIM`、拡張子 `.JBI.txt`、出力先は固定。
  書く前に、元との違いが「足した（消した）1回分の行」と「//NAME の1行」だけであることを確かめ、書いた後に読み戻して確かめる。

## 5. 確認表示・3D
- 見出し：「C00001〜C00003 の作業を 2回 → 3回 にします」
- 変わる命令の行：足す行（`+ 27行目  MOVL C00001 V=150.0` など）を差分で示す。
- 3D：変更前と変更後で、区間を何回通るかが分かるように、区間の位置の近くに「×2 → ×3」の印を出し、
  再生では区間の線ごとに「1回目」「2回目」「3回目」と数える（サーバーが区間の線ごとに `cycle` を付ける）。
  増やすとき、足した回の線（元からある線と同じ線）を変更後の色で重ねる。新しい位置・新しい線は描かない（作らないため）。
- MOVJ は直線で再生しない（今の S-MOVJ のまま。区間の種類 `kind` はサーバーの今の判定のまま）。
- 注意（固定文）：「同じ動きを1回ぶん足します。新しい位置・新しい移動の線は作りません」「サイクルの時間が長くなります」
  「検査を通ったことは、物理的な安全の保証ではありません」、および 0章の対象外の固定文。
  「安全です」「当たります」「干渉します」などは使わない。
- 画面の変更は、候補の表示・確認表示・3D の比較に必要な最小限だけ（見た目の直しは feat/ui-refresh の担当）。

## 8. 決めたこと・迷ったこと
- 2 → 1 は、唐川さんの決定で止めた（減らす変更は扱わない）。
- 「3回追加して」の選択肢：押せば範囲の確認に進むもの（2回 → 3回 になるもの）だけを出す（QA P1-2・Safety P2-1・P2-2）。
- 範囲の確認は、新しい操作（指示・比べる・［説明です］・位置の選択（ジョブに無い位置の選択も含む）・元に戻す・ほかのボタン）で捨てる（S-P2-2）。
- 区間のすぐ前・後ろに DOUT・TIMER の行があるときだけ、範囲の確認に「区間のすぐ前・後ろに信号（DOUT）や待ち時間（TIMER）の行があります
  （n行目「…」）。それらは繰り返しません」をプログラムが付ける（S-P2-4）。
- 回数の変更の候補を作ったときの上下の向きの照合の結果も、位置の移動と同じく承認のときに比べる（回数の変更には上下の言葉は無いが、ガードを変えないため）。
- 回数の変更の候補では、位置の選び直しで候補を捨てる（位置ごとの候補ではないため）。
- JBI の命令の行の数を持つ行（NPOS のような数）は INST 部には無い前提（`docs/JBI_FORMAT_NOTES.md` と同じく実機のサンプルで確認待ち）。
- 安全のガードのテスト `tests/test_c028_p0.py::test_b_only_session_propose_creates_candidates`（候補を入れる所は1か所）を、
  「位置の移動・速度は `_accept` の1か所、回数の変更は `_hear_repeat` の1か所（`plan_repeat` の結果だけ。plan_shift・参考の候補・解釈の係の提案は使わない）」の
  2か所に直した。回数の変更は解釈の係を通らない別の入口のため。レビューで確かめてほしい点。
- 回数の変更の発話では、画面で目立たせる「読めなかった言葉」を、決まった形で読めなかった言葉だけにする（「から」「作業」を目立たせない）。
- 実機の書式で、区間を続けてそのまま書いたジョブが実際にあるか、教示のときにどう書かれるかは未確認。

## 9. 内部レビュー（f11279b）のあとの直し
- 範囲の確認を待っている間に、声・文字で範囲を決めようとする言葉（「この範囲を繰り返す」「繰り返して」「はい」「そうそう」「OK」「お願いします」「承認して」など。
  `repeat_count.is_range_confirm_word`）には、確定せず、範囲の確認を残したまま「範囲は［この範囲を繰り返す］のボタンで決めてください（声や文字では決めません）」と案内する。
  打ち消し・別の指示・別の回数の指示は、今どおり範囲の確認を捨てる。
- 不正なボタンの値・古い turn で断ったときは、範囲の確認も捨てる（「もう使えません」の文と状態を合わせる）。
- 「3回」「3回お願いします」「C00001を3回」も回数の変更として読む。位置を1つだけ言ったときは、その位置を含む区間だけを示す。
  区間が0件のときは RANGE_NEEDED に対象外の文を添える。
- 「六回」「十回」「ろっかい」は回数として読み、2回から3回だけの理由で止める。マイナスの回数は止める。
- 区間の候補の探し方を軽くした（番号が1つずつ増える MOVL の並びで、1回分のすぐ後ろが同じ行で始まるものだけを確かめる）。
- 「3回から3回」「1回から3回」（言った今の回数が違い、目標が3回）は［合計3回にする］の1択で聞き返す。**唐川さんの判断待ち**（止めるか、このままか）。

- 従来の「選択肢のボタンは同じ重さ」の**例外として、範囲の確認の画面だけ**、［この範囲を繰り返す］を目立たせる。
- 承認ボタンとの区別は残す：色は青（承認はオレンジ）、文字は「この範囲を繰り返す」、ボタンの下に小さく「範囲を決めるだけです。承認は次の確認表示で行います」。
- ［違う］は控えめにしても、枠のある押せるボタンの見た目・文字を残す（style.css の `.quiet`）。
- 声だけでは確定できない（今のまま）。範囲の確認の最中の「承認」「承認して」には、
  「範囲を決めるのは［この範囲を繰り返す］のボタンです。承認は、そのあとの確認表示の承認ボタンで行います」と案内する。
- 範囲を確定しようとする短い文（「はいそうです」「この範囲をくりかえす」など。打ち消し・別の指示・数・位置を含まない）は、範囲の確認を残してボタンの案内を返す。
- 区間が見つからないときは「このジョブには、続けて2回以上書かれた移動の区間（1回分は2〜10行）が見つかりません」と言い、
  DOUT・TIMER のあるジョブのときだけ対象外の文を添える。ジョブに無い位置（「C00099を3回」）は「位置 C00099 はこのジョブにありません」で止める。
