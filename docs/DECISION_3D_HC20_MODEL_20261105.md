# 決定の記録：3D に HC20 を模した静止モデルを出す（2026-11-05 夜）

ブランチ：ui/3d-robot-base（基点 cf0b3fb = integrate/debug-1106）。画面のファイル（view3d.js・index.html・style.css・app.js の 2D の図の数行）とテストだけを変えた。サーバー・安全の判定・承認・出力・JOB の生成は変えていない。

## 唐川さんの決定
もとの仕様の「ロボット本体・関節は描かない」を変えて、**HC20 を模したロボットの形（台座・腕・関節）を、静止した 3D モデルとして表示する**。

- HC20 の外観：台座・腕・関節を含めた形を表示する
- JOB の位置：今の点・経路・札は、そのまま表示する
- ロボットの動作：今回は再現しない（静止モデル。ジョブの再生に合わせて動かさない）
- 安全の表示：実機の姿勢・可動範囲・干渉の判定を再現したものではない、とはっきり書く
- 座標系：台座の中心をロボット座標の原点 (0,0,0) に置き、ロボットの正面を X＋、上を Z＋ に向ける（安川のロボット座標。アプリはロボット座標（///POSTYPE ROBOT・///RECTAN）以外のジョブを止める）
- 大事な線引き：HC20 の形を見せることと、正確なロボットのシミュレーションは別

唐川さんの言葉（最初の依頼）：「3Dにロボット位置がわかるようにしたい。そうしないとどっちにうごかすかわかりにくい」

## 作り方の決まり
1. 形のデータは自分で作った。円柱（台座・胴・肩・下の腕・肘・上の腕・手首）を組み合わせ、今の view3d.js の SVG の投影で描く。安川電機の CAD データ・画像・ロゴは取ってこない・使わない（ライセンスを確かめていないため）。札は「HC20 を模した簡易モデル（メーカーの形状データではありません）」。
2. 寸法は目安。届く範囲 約 1700mm（公開の値）に全体が合うように決めた値で、実機の各部の寸法を調べて決めたものではない。1か所の定数 `HC20_DIMS`（view3d.js）にまとめ、「目安。唐川さんの確認待ち」と注釈を付けた。
3. 姿勢は決まった1つ（下の腕を少し正面へ傾けて立て、上の腕を正面へ出して少し下げ、手首は下向きの待機の姿勢の目安。`HC20_POSE`）。ジョブの点と関係なく、腕の先がジョブの点に届いて見える必要はない。図の左上に「ロボットの姿勢は、実機・ジョブの動きと関係ありません（目安の静止モデル）」と出す。
4. 見やすさ：モデルは半透明の面と細い線で、点・経路・札の下に描く（押しても選ばれない）。正面（X＋）の矢印と「ロボットの正面（X＋）」、台座の札「ロボット（台座の中心）」を出す（モデルを隠しても残す）。札はほかの札（点の名前・変更の札・回数の札・人が教えた札・右上の窓・軸の文字）と重ならない所に置く。3D の上の欄に［モデルを隠す］／［モデルを出す］のボタンを1つ足した（既定は表示。ページの中だけで、保存しない）。最初の視点と［視点を戻す］で、モデルの全体と点の両方が入る。
5. 2D の図（Y・Z、X・Z、X・Y）：モデルの輪郭は入れない。原点の印と札、X＋（正面）の向きの印だけ。Y・Z では X＋ が図の面に垂直なので、矢印を描かず「ロボットの正面（X＋）：この図の面に垂直」と書く。
6. 注意書き：「ロボット本体・関節は描いていません」を「ロボットの形は、HC20 を模した目安の静止モデルです（メーカーの形状データではありません）。実機の姿勢・寸法・可動範囲・干渉を再現したものではありません。」に直した（図の下と確認表示）。「動作や干渉を保証するシミュレーターではありません」「この図で離れて見えても、当たらないとは限りません」「参考表示であり、実際のロボットの動きではありません」は残した。「台座の印は、ロボット座標の原点（0,0,0）の位置です。」を足した。
7. 「上」「右」「手前」などの向きの言葉は、札に入れていない（画面ごとに向きを確かめる仕組みが別の担当で作業中のため）。軸の名前と「ロボットの正面（X＋）」だけ。

## もとの仕様との違い
| | もとの仕様 | 今回 |
|---|---|---|
| ロボット本体・関節 | 描かない | HC20 を模した静止モデルを描く（目安。隠せる） |
| 注意書き | 「ロボット本体・関節は描いていません」 | 「ロボットの形は、HC20 を模した目安の静止モデルです…再現したものではありません」 |
| 3D の最初の視点 | ジョブの点だけで枠に収める | 点・原点・モデルの全体で枠に収める（点は小さく見える。ホイールで拡大できる。モデルを隠すと点に合わせて収め直す） |
| 床の格子 | いちばん下の点の少し下 | 点がどれも Z≥0 なら Z=0（台座の面）。Z<0 の点があれば、いちばん下の点の少し下 |
| 2D の図 | 点だけで広さを決める | 原点も入れて広さを決める（点は小さく見えることがある） |

## 残るリスク
- 形や大きさから、届く・届かない・当たる・当たらないを読み取られるおそれ。モデルは目安の寸法と決まった姿勢で、実機の姿勢・寸法・可動範囲・干渉を再現していない。注意書きで伝えるが、見た目の印象は文より強い。
- 寸法は目安で、唐川さんの確認待ち。実機の HC20 と比べて、腕の長さ・台座の大きさ・肩の高さが違って見える。
- 姿勢がジョブの点と関係ないため、「この姿勢でこの点に行く」と誤解されるおそれ。図の左上と図の下に、姿勢は関係ないと書いた。
- 3D の向き（画面の上下・左右がロボットのどちらか）は、画面ごとの確かめがまだ。札に向きの言葉は入れていない。
- サーバー側の注意の文（api.py・inspect_job.py の「腕やツールの根元は描いていません」）は、今回の範囲の外で変えていない。モデルを描いた今、この文の受け取られ方は唐川さんの確認が要る。
- 点が原点から遠く、点の広がりが小さいジョブでは、最初の視点で点がとても小さく見える（拡大するか、モデルを隠す）。
- 内部レビューはサブエージェント（同じ Claude）で行う。外部の独立レビュー（チャッピー）の代わりにはならない。
