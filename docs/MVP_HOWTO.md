# まず動くもの（MVP）の使い方：シミュレーションモード

合成ジョブ（`samples/dummy/` の架空のジョブ）で、次の流れを画面で一通り試すためのものです。

JBI読込 → 位置選択 → 文字の指示 → 変更候補 → プレビュー（変更前後の図と差分） → ボタン承認 → シミュレーション用のJBI出力（`output/sim/`）

- **音声入力は別作業で準備中です。今は文字入力で操作します。** 画面には「音声入力は準備中」の置き場所だけがあります。
  音声が後でつながるときも、同じ `/api/hear`（`source` が `voice`）に送る形です。
- **解釈は偽のClaude（モック）です。** 本物の Claude は呼びません。モックは、プログラムが発話から取り出した事実
  （位置番号・量・軸・操作の種類）だけで道具の引数を作ります。事実で足りなければ提案しません。作業ログに「モック」と出ます。

## 起動

```
python -m voice_teaching.web            # http://127.0.0.1:8765/
python -m voice_teaching.web --port 0   # 空いているポートで起動（表示された URL を開く）
```

- 127.0.0.1 だけで待ち受けます。止めるときは Ctrl+C。
- Chrome で表示された URL を開きます。
- 読み込んだジョブと画面の状態はサーバーのメモリの中だけにあり、ディスクに保存しません（サーバーを止めると消えます。
  画面を8つ以上開くと古いものから捨てます。そのときは読み込み直してください）。

## 操作の手順（ダミーで試す）

1. 「JBIファイルを選ぶ」で `samples/dummy/DEMO_PLACE.JBI` を選ぶ。
2. 図の点か「位置の一覧」の行をクリックして、位置（例：C00004）を選ぶ。文字で「C00004を選択して」でもよい。
3. 「文字で指示」に入れて「指示を送る」。例：
   - `この位置をY方向に10mm移動して`
   - `C00004をZ方向に-5mm移動して`
   - `C00000をX方向に10mm移動して`（共用の位置。実機用の検査では止まり、シミュレーションだけの候補になる。理由が赤で出る）
   - 聞き返しになる例：`この位置を少し動かして`（量がはっきりしない）、`置く位置を右に10ミリ`（左右は枠の設定が無いので使えない）
   - 止まる例：`承認して`・`OK`・`はい`・`書き出して`（承認・出力はボタンだけ）、`スタートして`（ロボットは動かさない）
4. 「聞き取った文字（そのまま）」と「解釈（プログラムが発話から取り出したこと）」が別々に出る。聞き返し・止めた理由もここに出る。
5. 変更候補ができると、画面いっぱいの確認表示が開く。文はプログラムが変更候補から作ったもの
   （例：「位置 C00004 を Y方向に +10.000mm 動かします（Y：190.000 → 200.000）。…これでいいですか？」）。
   実機用の検査で止まった候補なら、その理由が赤で出る。
6. 確認表示で、承認する人の名前を入れて「承認する（ボタンだけ）」を押す。閉じれば承認しない。
   「変更候補のプレビュー」の欄で、変更前後の行（差分）・変わる命令の行・注意を見られる。図には変更前（灰色）と変更後（色付き）が出る。
7. 承認した後だけ「シミュレーション用に出力（合成ジョブだけ・実機に入れない）」が押せる。
   出力したファイルの場所が出る（`output/sim/DEMO_PLACE_SIM.JBI`）。元との違いは、位置の1行と `//NAME` の1行だけ。
8. 承認の後で、新しい指示・位置の選び直し・「元に戻す」をすると、承認は取り消され、出力ボタンは使えなくなる。

右側の「作業ログ」に、発話・モックの道具の呼び出し・候補・聞き返し・止めた理由・承認・出力が順に出ます。

## できること・できないこと

| できる | できない（作っていない） |
|---|---|
| 文字の指示で、1つの位置を X・Y・Z のどれかに動かす変更候補を作る | 音声入力（別作業で準備中） |
| 変更前後の図・差分・変わる命令の行・注意を見る | 本物の Claude での解釈（今はモック） |
| 承認ボタンでの承認（名前が要る） | 声や文字での承認・出力 |
| 合成ジョブだけ、シミュレーション用に新しいジョブ名で `output/sim/` に出力 | 実機用のジョブの出力・転送・ロボットの起動 |
| 元のジョブを残す（変えない。同じ名前のファイルは上書きしない） | 速度の変更（専門家の枠の値が無いので止まる）、左右・前後の指示 |

- シミュレーションの出力は合成ジョブ（`samples/dummy/` のファイルとバイト単位で同じもの）だけです。ほかのジョブは、承認しても出力の所で理由を出して断ります。
- 出力したものは実機に入れないでください。図や検査は参考で、変更後の経路は人が確かめます。
- 1回に動かす量は、仮の上限（確認待ち）50mm までです。

## API（127.0.0.1 の画面から使う）

| 経路 | 本文 | 内容 |
|---|---|---|
| `POST /api/load` | JBI のバイト列 | 読み込み。新しい `session_id`、ジョブの内容（`view`）、状態（`state`）を返す |
| `POST /api/select` | `{session_id, position}` | 位置を選ぶ（承認があれば取り消す） |
| `POST /api/hear` | `{session_id, text, source: "voice"\|"text"}` | 指示。Session.hear → モック → 変更候補。承認・出力は呼ばない（承認があれば取り消す） |
| `POST /api/compare` | `{session_id}` | 変更前後の比較 |
| `POST /api/undo` | `{session_id}` | 候補を捨てる（承認があれば取り消す） |
| `POST /api/state` | `{session_id}` | 今の状態 |
| `POST /api/approve` | `{session_id, approver}` | 承認（画面の承認ボタンからだけ呼ぶ。名前が要る） |
| `POST /api/export` | `{session_id}` | シミュレーション用の出力（承認した後だけ。合成ジョブだけ） |

前からある `POST /api/parse`・`/api/preview/shift`・`/api/preview/speed`（読むだけ）も残っています。
