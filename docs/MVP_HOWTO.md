# まず動くもの（MVP）の使い方：シミュレーションモード

合成ジョブ（`samples/dummy/` の架空のジョブ）で、次の流れを画面で一通り試すためのものです。

JBI読込 → 位置選択 → 音声または文字の指示 → 変更候補 → プレビュー（変更前後の図と差分） → ボタン承認 → シミュレーション用のJBI出力（`output/sim/`）

- **音声入力**は、引き継ぎ（別チャット）の `speech.js`（コミット fd03d84 の `voice_teaching/static/speech.js` を無変更で
  `voice_teaching/web/static/speech.js` に置いたもの。テストは `tests/speech.test.mjs`、import 先だけ変更）でつないでいます。
  認識した文は文字入力の欄に入るだけで、自動では送りません。人が確かめて直してから「指示を送る」を押します。
  音声も文字も同じ `/api/hear` に送ります（`source` は記録だけで、結果は変わりません）。
- **解釈**は、環境変数 `ANTHROPIC_API_KEY` があれば本物の Claude（公式 SDK `anthropic`）です。キーが無ければ起動を止めます。偽のClaude（モック）は `--mock` を付けて起動したときだけです。
  どちらで解釈しているかは、画面と作業ログに出ます。

## 起動

```
python -m voice_teaching.web --mock            # キーなしで試す（モック）。http://127.0.0.1:8765/
python -m voice_teaching.web --mock --port 0   # 空いているポートで起動（表示された URL を開く）
```

（`--mock` はモックで試すとき。本物の Claude で動かすときは `--mock` を外し、キー（`.env`）を用意する。キーが無いまま `--mock` なしで起動すると止まります。撮影（`--channel filming`）では `--mock` は使えません）

- 127.0.0.1 だけで待ち受けます。止めるときは Ctrl+C。
- Chrome で表示された URL を開きます。
- 読み込んだジョブと画面の状態はサーバーのメモリの中だけにあり、ディスクに保存しません（サーバーを止めると消えます。
  画面を8つ以上開くと古いものから捨てます。そのときは読み込み直してください）。

## 本物の Claude を有効にする

1. `python -m pip install -r requirements.txt`（`anthropic` が入ります。Apache License 2.0）
2. リポジトリ直下に `.env` を作り、次を書く（`.env` は `.gitignore` で除外済み。コミットしない）。
   ```
   ANTHROPIC_API_KEY=（本人のキー）
   ANTHROPIC_MODEL=claude-opus-5-5   # 任意。無ければ claude-opus-5-5
   ```
   環境変数に同じ名前があれば、そちらが使われます。キーをコードやログ、チャットに書かないでください。
   会社のPCにキーを置かない方針なら、本人の家のPCで試してください。
3. 起動の前に `python -m voice_teaching.claude_check` で点検できます（通信しない。詳しくは `docs/CLAUDE_API.md`）。
4. 起動すると「解釈：本物の Claude（claude-opus-5-5）」と表示されます。キーが無ければ「偽のClaude（モック）」。
- Claude に送るのは、指示の文・選んでいる位置番号・位置番号の一覧です（座標値・ジョブ名は送りません）。「置くところ」などの場所の言葉のときだけ、架空のサンプル（合成ジョブ）の命令の行と行番号も送ります。それ以外のジョブの中身は送りません（docs/CLAUDE_API.md 3章・6章）。
- Claude の道具は `propose_position`（位置・方向 上/下/右/左/X±/Y±/Z±・量 mm）と `ask_user` だけです。上→Z+、下→Z−。
  右・左は軸が決まっていないので聞き返します。Claude の結果も、発話の事実との照らし合わせ（`check_proposal`）を必ず通ります。
- キーがあるのに失敗したとき（`anthropic` が入っていない・通信失敗・異常な応答・Claude が断った）は、モックへ切り替えず、
  原因ごとの決まった文（キー・モデル名・混雑・ネットワーク など。`docs/CLAUDE_API.md` 4章）で止まります。キーや生のエラーは画面に出しません。

## 操作の手順（ダミーで試す）

1. 「JBIファイルを選ぶ」で `samples/dummy/DEMO_PLACE.JBI` を選ぶ。
2. 図の点か「位置の一覧」の行をクリックして、位置（例：C00004）を選ぶ。文字で「C00004を選択して」でもよい。
3. 文字で指示するときは「文字で指示」に入れて「指示を送る」。音声で指示するときは下の「音声の使い方」。例：
   - `この位置をYプラス方向に10mm移動して`、`この位置をZのプラス10mm`
   - `この位置を上に10mm`：上下の向きの設定（README「上下の向きの設定」）の照合に通ったときだけ Z＋10。通らなければ「Zプラス・Zマイナスで言ってください」と聞き返す（CHECKER_026 M2）
   - `C00004をZ方向に-5mm移動して`
   - `C00000をXプラス方向に10mm移動して`（共用の位置。実機用の検査で止まり、参考の表示だけの候補になる。理由が赤で出る。**承認も出力もできない**）
   - 聞き返しになる例：`この位置を少し動かして`（量がはっきりしない）、`置く位置を右に10ミリ`（左右は枠の設定が無いので使えない）
   - 止まる例：`承認して`・`OK`・`はい`・`書き出して`（承認・出力はボタンだけ）、`スタートして`（ロボットは動かさない）
4. 「聞き取った文字（そのまま）」と「解釈（プログラムが発話から取り出したこと）」が別々に出る。聞き返し・止めた理由もここに出る。
5. 変更候補ができると、画面いっぱいの確認表示が開く。文はプログラムが変更候補から作ったもの
   （例：「位置 C00004 を Y方向に +10.000mm 動かします（Y：190.000 → 200.000）。…これでいいですか？」）。
   実機用の検査で止まった候補なら、その理由が赤で出る。
6. 確認表示で、承認する人の名前を入れて「承認する（ボタンだけ）」を押す。閉じれば承認しない。
   「変更候補のプレビュー」の欄で、変更前後の行（差分）・変わる命令の行・注意を見られる。図には変更前（灰色）と変更後（色付き）が出る。
7. 承認した後だけ「シミュレーション用に出力（合成ジョブだけ・実機に入れない）」が押せる。
   出力したファイルの場所が出る（`output/sim/DEMO_PLACE_SIM.JBI.txt`）。元との違いは、位置の1行と `//NAME` の1行だけ。
8. 承認の後で、新しい指示・位置の選び直し・「元に戻す」をすると、承認は取り消され、出力ボタンは使えなくなる。

右側の「作業ログ」に、発話・モックの道具の呼び出し・候補・聞き返し・止めた理由・承認・出力が順に出ます。

## 音声の使い方

1. ジョブを読み込み、位置を選ぶ。
2. 「音声の処理方法」を選ぶ（最初は未選択で、選ぶまで録音できません）。
   - **ブラウザー標準**：Chrome などの方式によって、音声がブラウザー提供元（Chrome では Google）のサーバーで処理されることがあります。
     このアプリは音声を保存・送信しませんが、ブラウザー側の処理を止めたり取り消したりはできません。
   - **端末内のみ**：対応するブラウザーと日本語の言語パックが要ります。使えないときは止まり、外部の処理へは切り替えません。
3. 「マイクで話す」→ 話す（例：「この位置を上に10ミリ」）→「終了」。未確定の文は表示だけで、使いません。
   「取消」なら、認識した文は使わず、文字入力の欄も変わりません。
4. 認識した文が文字入力の欄に入る。確かめて、必要なら直して「指示を送る」を押す（自動では送りません）。
5. 録音中は、ジョブの読込・位置の選択・指示を送る・承認・出力・比べる・元に戻す が使えません（終了と取消だけ）。
6. 声で「承認して」「OK」「書き出して」と言っても、承認・出力はしません（ボタンだけ）。
- 音声認識の無いブラウザーでは「このブラウザでは音声入力を使えません。文字で入力してください」と出ます。

### 実マイクで確かめる手順（唐川さん向け。まだ誰も確かめていません）
1. `python -m voice_teaching.web --mock`（本物の Claude で試すときは `--mock` を外し、キーを用意する）で起動し、Chrome で開く。
2. DEMO_PLACE.JBI を読み込み、C00004 を選び、「ブラウザー標準」を選ぶ。
3. 「マイクで話す」→ マイクの許可を聞かれたら許可 →「この位置を上に10ミリ」と話す →「終了」。
4. 入力欄の文を確かめる（「10ミリ」が「十ミリ」などになると量が分からず聞き返しになります。そのときは直して送る）。
5. 「指示を送る」→ 確認表示に「Z方向に +10.000mm」→ 名前を入れて承認 → 出力。
6. ほかに：マイクを拒否したとき・何も話さず終了したとき・取消・録音中にボタンが押せないこと、を見る。
7. 本物の Claude で試すなら、`.env` にキーを置いて起動し直し、同じ操作をする（作業ログに「Claude」と出る）。

## できること・できないこと

| できる | できない（作っていない） |
|---|---|
| 音声または文字の指示で、1つの位置を X・Y・Z のどれかに動かす変更候補を作る | 音声での承認・出力・送信（認識文は入力欄に入るだけ） |
| 変更前後の図・差分・変わる命令の行・注意を見る | 「手前に」のような向きの言葉（FRAME の向きの表が無いため止める） |
| 承認ボタンでの承認（名前が要る） | 声や文字での承認・出力 |
| 合成ジョブだけ、シミュレーション用に新しいジョブ名で `output/sim/` に出力 | 実機用のジョブの出力・転送・ロボットの起動 |
| 元のジョブを残す（変えない。同じ名前のファイルは上書きしない） | 速度の変更（専門家の枠の値が無いので止まる）、左右・前後の指示 |

- シミュレーションの出力は合成ジョブ（`samples/dummy/` のファイルとバイト単位で同じもの）だけです。ほかのジョブは、承認しても出力の所で理由を出して断ります。
- 実機用の検査で止まった候補（赤い理由が出るもの）は、合成ジョブでも承認・出力できません（CHECKER_019 R1）。図と差分で確かめるだけです。
- 出力は、拡張子 `.JBI.txt`（例 `DEMO_PLACE_SIM.JBI.txt`）で、シミュレーション専用のフォルダ `output/sim/` だけに書きます。出力先は画面からもプログラムの呼び出しからも選べません（USB などへ直接は書きません）。JBI の中身に警告のコメントは足しません（CHECKER_019 R6）。
  **拡張子・出力先・ジョブ名の `_SIM` は、取り違えを減らすためのもので、実機での誤使用を完全に防ぐものではありません。**
- 出力したものは実機に入れないでください。図や検査は参考で、変更後の経路は人が確かめます。
- 1回に動かす量は、上限 20mm までです（仕様v2.1 のデモ案の値。同じ位置の累積も軸ごとに 20mm まで。累積の 20mm は、専門家の枠（FRAME）を実装するまでの暫定です。安全の保証ではありません）。

## API（127.0.0.1 の画面から使う）

| 経路 | 本文 | 内容 |
|---|---|---|
| `POST /api/load` | JBI のバイト列 | 読み込み。新しい `session_id`、ジョブの内容（`view`）、状態（`state`）を返す |
| `POST /api/select` | `{session_id, position}` | 位置を選ぶ（承認があれば取り消す） |
| `POST /api/hear` | `{session_id, text, source: "voice"\|"text"}` | 指示。Session.hear → モック → 変更候補。承認・出力は呼ばない（承認があれば取り消す） |
| `POST /api/compare` | `{session_id}` | 変更前後の比較 |
| `POST /api/undo` | `{session_id}` | 候補を捨てる（承認があれば取り消す） |
| `POST /api/state` | `{session_id}` | 今の状態 |
| `POST /api/approve` | `{session_id, approver}` | 承認（画面の承認ボタンからだけ呼ぶ。名前が要る） |
| `POST /api/export` | `{session_id}` | シミュレーション用の出力（承認した後だけ。合成ジョブだけ） |

前からある `POST /api/parse`・`/api/preview/shift`・`/api/preview/speed`（読むだけ）も残っています。
