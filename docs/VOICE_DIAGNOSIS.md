# 音声入力の「通信に失敗しました」の調査と直し（2026-11-03 朝）

唐川さんの朝の確認で「音声認識の通信に失敗しました。接続を確認して、録音し直してください。」が出た。
推測で決めずに、再現の条件と確かめた結果を残す。

- 対象：`feat/3d-voice` の edab41b（直しは `feat/voice-stable`）
- この PC：Windows 11 Pro、Google Chrome 156.0.8078.76、Microsoft Edge 151、WebView2 151.0.4129.101
- マイク（Windows の既定）：EMEET SmartCam C960（ほかに Intel のマイク配列、Realtek の外付けマイク）

## 1. 結論

| 項目 | 判定 | 根拠 |
|---|---|---|
| 朝の画面を開いたブラウザー | **Google Chrome ではなく、ChatGPT（Codex）のアプリの中のブラウザー** | そのブラウザーの履歴（`…\OpenAI.Codex_…\Codex\Default\Partitions\codex-browser-app\History`）に `http://127.0.0.1:8765/?utm_source=chatgpt.com` の訪問が 11-03 05:35（＝サーバーの記録の 05:35 と同じ）、11-02 22:16・20:20。Google Chrome の履歴では、このアプリの最後の訪問は 11-02 20:39 |
| エラーの原因 | **可能性が最も高い：アプリの中のブラウザー（Electron・Chromium 151）では、声を文字にする Google のサービスを使えない** | アプリの中のブラウザー・Electron では、`webkitSpeechRecognition` が `network` を返す報告が多い（下の出典）。**そのブラウザーでの再現は未**（Node.js・Electron がこの PC に無く、ChatGPT のアプリを操作して試すことはしていない） |
| マイクの許可・入力デバイス | 問題なし | 実際の Chrome で getUserMedia が通り、既定のマイク（EMEET）から音が届いた（下の 2） |
| Chrome の音声認識（ブラウザー標準） | **使える** | 実際の Chrome 156・実マイクで「この位置を上に2 mm」と文字になった（下の 2）。`network` は一度も出なかった |
| 外部の音声認識サービスへの接続 | つながる | 同上。プロキシの設定なし（ProxyEnable=0）、Chrome のポリシーなし |
| 「端末内のみ」の日本語 | **この PC では使えない（タブが落ちる）** | 日本語の音声データは `install()` で約11秒で入る。そのあと話すと、話し終わった直後にタブが落ちた（4回中4回。声が届かなかった1回を除く）。`available()` は入れた後も `downloadable` と返す |
| 開始・終了・再開の処理 | 問題なし | 実際の Chrome で、続けて7回、OFF→ON のあとも、`network` なし。マイクを OFF にしたときの `aborted` だけ（意図どおり） |

## 2. 実マイクで確かめたこと

方法：実際の Google Chrome（Playwright で起動、**偽のマイクは使わない**、新しいプロファイル）。
人が話す代わりに、**スピーカーから Windows の音声合成（Haruka）で話し、実マイク（EMEET）で拾った**。
人の声での確認は未（唐川さんの確認が要る）。

### ブラウザーごとの「ブラウザー標準」

| ブラウザー | 結果 |
|---|---|
| Google Chrome 156 | 「この位置を上に2 mm」（final）。`network` なし |
| Microsoft Edge 151 | 「この位置を、上に美里。」（Microsoft のサーバー。2ミリ を聞き違えた） |
| Playwright 同梱の Chromium 156 | 「この位置を上に2 mm」（Chrome 以外でも使えるものがある。だから Chrome 以外を一律に止めない） |
| ChatGPT（Codex）のアプリの中 | 未確認（上の 1） |

### アプリの画面を通して（直した後：同意 → 続けて話す → OFF → ON）

| 話した文 | Chrome が返した文 | アプリの結果 |
|---|---|---|
| この位置を上に2ミリ | この位置を上に2 mm | 候補 Z +2.000 |
| Yプラス3ミリ | ワイプラス 3mm（別の回は「Y +3 mm」） | 候補 Y +3.000 |
| Yのプラス3ミリ | Y の +3 mm（別の回は「Y の Plus 3ミリ」） | 候補 Y +3.000 |
| Xのマイナス5ミリ | X の -5ミリ | 候補 X −5.000 |
| Xマイナス5ミリ | **x5ミリ**（3回とも「マイナス」が落ちた） | 聞き返し（向きを推測しない）。「向きが聞き取れていません」の知らせ |
| Yプラスに3ミリ | **Y +23 mm**（2回とも「に3」が「23」に） | 上限 20mm の検査で止まる |
| Xマイナス方向に5ミリ | **X 方向に 5mm**（マイナスが落ちた） | 知らせを出す。**このまま送ると候補 X +5.000**（向きの無い軸は＋という今の決まり） |
| この位置を下に3ミリ | この位置を下に 3mm | 候補 Z −3.000 |
| マイクを OFF → ON | — | 続けて聞けた |

分かったこと：短い「X」「Y」の後の「マイナス」「プラス」は落ちやすい。**「Xのマイナス5ミリ」「Yのプラス3ミリ」と「の」を入れると、符号が残った**。

## 3. 直したこと

- **Chrome 以外の案内**：Google Chrome・Edge でなければ、マイクの下に「音声入力は Google Chrome で開いてください」と「アドレスをコピー」。
  そこで通信に失敗したら、聞き直さずに「このブラウザーでは、声を文字にできません。Google Chrome で開いてください」
- **方式を選ばなくてよい**：初めて 🎤 を押したときに「声を文字にするため、Chrome が音声を Google のサーバーへ送って文字にします。このアプリは音声を保存しません。」と出して、「使う」「文字で入力する」を聞く（**同意するまで送らない**。勝手に方式を切り替えない）。
  同意はこのブラウザーに覚える。方式（ブラウザー標準／端末内のみ（試験的））は詳細表示へ
- **Web会議のように**：声が無いまま止まったら（no-speech）、マイク ON のまま聞き直す（20回まで。3分話さなければ OFF は今のまま）。
  通信の失敗は、Chrome・Edge なら1回だけ聞き直す。続けば OFF にして「接続を確かめて、もう一度 🎤」と文字の入力へ
- **失敗ごとの短い案内**：マイクの許可（アドレス欄の左のマークから許可）、マイクが見つからない（接続・Teams・Zoom）、端末内のみの日本語
- **読み方**：「Xマイナス5ミリ」「Y +3 mm」「X の -5ミリ」「ワイプラス 3mm」「Y の Plus 3ミリ」「X − 5 mm」を読む。
  「マイナス」が落ちた「x5ミリ」は推測しないで聞き返す。「ワイヤー」「ワイ3mm」は軸にしない
- **向きの知らせ**：声から入った文に軸があって向き（＋・−）が無ければ、「向き（プラス・マイナス）が聞き取れていません。このまま送ると＋として扱います。マイナスなら文を直してください」

変えていないこと：speech.js（引き継ぎのファイル）、承認・出力（ボタンだけ）、上限 20mm、上・下＝Z±、右・左の聞き返し、向きの無い軸＝＋の決まり（サーバー）、音声と文字で結果が同じこと。

## 4. ローカルの音声認識エンジン（比べた結果・入れていない）

Chrome の「ブラウザー標準」が Chrome では安定して使えたので、今回は入れていない。

| 方式 | 通信 | この PC での結果 | 入れるなら |
|---|---|---|---|
