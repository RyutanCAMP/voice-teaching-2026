# 音声・文字の指示を「変更候補」にするまでの設計（P2）

仕様v2.1 の 4章（画面B）・5章（Claudeの活用）・6章（安全の設計）・8章（音声）・11章（受入テスト）に合わせた設計メモです。
この段階で作るのは、発話を読み取る部分（`voice_teaching/utterance.py`）と、画面の状態を持つ部分（`voice_teaching/session.py`）だけです。
画面（HTML/JS）と、Claude を呼ぶ部分はまだ作りません。承認・書き出し・転送も、この段階では作りません。

## 1. 流れ

```
[マイク] Chromeの音声認識 ─┐
                          ├→ 聞き取った文字 → session.hear(文字, source)   … 文字をそのまま画面に出す
[文字入力] ───────────────┘                    │
                                               ├ プログラムだけの読み取り（utterance.read_utterance）
                                               │   ・はっきり書かれた事実だけを取り出す（位置番号・量・軸・操作の種類）
                                               │   ・止める／聞き返す ものはここで決まる（pre_check）
                                               ↓
                                   解釈：Claude API の道具の使用（今はモック）
                                     select / propose_change / compare / undo / ask_user を呼ぶ
                                               ↓
                                   session.propose(道具の引数)
                                     1) 発話の事実と照らし合わせる（utterance.check_proposal）
                                     2) ジョブの検査（jbi.plan_shift / plan_speed）
                                     → 通らなければ理由を返し、何も変えない。この発話ではもう提案を受け付けない
                                               ↓
                                   変更候補（jbi.ChangeProposal）… 元のジョブは変わらない
                                               ↓
                                   プレビュー（session.compare：変更前後の行と値・前後の区間）
                                               ↓
                                   大きな確認表示（文はプログラムが差分から作る）
                                               ↓
                                   ボタンで承認（次の段階。音声・文字では承認しない）
```

- 音声入力と文字入力は、`session.hear` に入った時点で同じ流れになる（受入テスト22）。`source` は記録のためだけに持ち、結果を変えない。
- 画面には「聞き取った文字（そのまま）」と「プログラム・Claudeの解釈」を分けて出す（仕様8章）。

## 2. 役割の分け方

| 役 | 担当 | やらないこと |
|---|---|---|
| 耳 | Chromeの音声認識（Web Speech API, `ja-JP`）。音声は Google のサーバーで処理される（READMEで開示） | 解釈 |
| 読み取り | `utterance.py`（プログラム） | あいまいな言葉を推測で数字にしない |
| 頭 | Claude（道具の使用）。対象の特定・聞き返し・言い換え | ジョブの文字列を書かない。軸を決めない。数字を作らない |
| ルール | `utterance.check_proposal` と `jbi.plan_shift` / `plan_speed` | 物理的な安全の保証 |
| 最終判断 | 人：画面で確かめてボタンで承認、実機での確認とスタート | ― |

## 3. Claude はジョブの文字列を書かない・数字は道具の引数として出すだけ

- Claude が変更を出す手段は、道具 `propose_change` の引数だけ。引数として受け付けるのは
  `kind`（`shift` / `speed`）、`position`（C00005 の形）、`axis`（X/Y/Z）、`side`（右/左）、`delta_mm`、`percent` だけ。
  これ以外のキー（変更後の行、説明文など）が入っていたら、その提案は使わずに止める（`ProposedChange.from_tool_args`）。
- 引数の数字は、利用者が言った量と同じでなければ聞き返す（受入テスト16）。利用者が量を言っていない（漢数字・「半分」・単位が無い数字を含む）ときは、Claude が数字を出しても使わない（受入テスト5）。
- 「右」「左」はプログラムが枠の設定の軸に変える。**枠の設定がまだ無いので、今は左右の指示は候補にしない**（受入テスト7）。発話は聞き返し（X・Y・Z か上げる・下げるで言い直してもらう）、Claude が `side` を出したら止める。
- 「X方向に10mm」のように軸がはっきりした指示は、枠の設定が無くても候補にする（シミュレーションモード。1回の移動量の上限は jbi の仮の値 50mm）。
- 速度の `percent` は「今の速度に対する割合」。新しい `V=` はプログラムが計算し、小数第1位に丸める（仕様5-2）。速度の1回の変更量の上限は専門家の枠で決めるもので、**枠の値が渡されていなければ速度は変えない**。
- 確認表示の文は、検査を通った変更候補の差分からプログラムが作る（`session.confirmation_text`、受入テスト17）。
- Claude に文を書かせるときは、数字の所を `{範囲まで}` のような空欄にさせ、プログラムが値を入れる（`utterance.fill_blanks`）。空欄以外に数字がある文、断定の言葉がある文、知らない空欄がある文は使わず、固定文にする（受入テスト14・18）。

## 4. 1つの発話の中での決まり

- 「発話」は、利用者が新しく話した（入力した）1文ごと。`session.hear` を呼ぶたびに新しい発話になる。
- 発話の中で、検査に断られた・聞き返しになった・止まった あとは、その発話では `propose` を受け付けない（受入テスト15）。Claude が量を変えて出し直すことはプログラムで止める。
- 聞き返しへの答え（「10ミリ」のように操作の言葉が無い1文）は新しい発話として扱い、前の発話で分かっていたこと（位置・軸）に答えの量を足して読む。
- 1回の提案で変えるのは1つの位置、または1つの命令だけ。2つ以上の位置・量・軸・操作が入った発話や、2つ以上の提案は聞き返す（受入テスト11）。
- 承認待ちの候補があるときに新しい提案が来たら止める（比べるか、元に戻してから指示してもらう）。候補を黙って重ねない。

## 5. 誤認識・聞き返し・止める

| 状況 | 結果 | 例 |
|---|---|---|
| 量が無い／漢数字・「半分」など／単位が無い数字・mm以外の長さの単位 | 聞き返す | 「何mm動かしますか？」 |
| 方向が無い／2つ以上ある／向きの指定が2つ | 聞き返す | |
| 位置番号の形が違う（C と5桁の数字でない） | 聞き返す | 「C0005」 |
| 位置番号が2つ以上 | 聞き返す | 「C00004とC00005を…」 |
| 提案が発話と食い違う（量・向き・軸・位置・種類） | 聞き返す | 10mm と言ったのに 15mm の提案 |
| 右・左（枠の軸が未設定） | 聞き返す（Claude の左右の提案は止める） | 「置く位置を右に10ミリ」 |
| 前・後ろ（今回は扱わない） | 止める | |
| 承認・書き出し・転送を声や文字で求めた | 止める（ボタンで行うと返す） | 「はい」「OK」「書き出して」 |
| ロボットの起動を求めた | 止める（アプリからは動かさない） | 「スタートして」 |
| ジョブの検査に断られた | 止める（理由をそのまま返す） | 存在しない位置、共用の位置、上限超え |

- 聞き取った文字はそのまま画面に出すので、誤認識に利用者が気づける。言い直し・文字での修正は新しい発話になる。
- **音声だけでは何も確定しない**。変更候補は承認されるまでジョブにならない。元のジョブはどの操作でも変わらない（`undo` 後もバイト一致）。
- **実機へは書かない**。このモジュールには承認・書き出し・転送・ロボット起動のメソッドを置かない。

## 5-2. シミュレーションモード（合成ジョブで一通り動かす）

- `jbi.plan_shift` / `plan_speed`（実機用の検査）に断られたとき、`Reply` は `blocked_reason`（断られた理由）と `candidate_made`（候補を作れたか）を分けて返す。
- `Session(simulate=...)` を渡したときだけ、断られた提案でもプレビュー用の候補を作れる（後で `voice_teaching/sim.py` が作る）。その候補には `candidate_blocked_reason` が付き、比較の注意書きと確認表示に「シミュレーションだけの候補」「実機用の検査では止まりました：（理由）」が出る。
- 発話との照らし合わせ（量・位置・軸・種類の食い違い、左右、2つ以上の変更、量が分からない）で断られたものは、`simulate` があっても候補にしない。
- 実機用の検査に断られた発話でも、その発話ではもう提案を受け付けない（受入テスト15）。

## 6. なぜ Claude を呼ぶ部分をまだ作らず、偽の Claude（モック）で試すのか

1. **APIキーは本人のPCにだけ置く**【決定】。昼の開発環境にはキーが無いので、本物の Claude は呼べない。
2. 安全の線引きは**プログラム側**にある（照らし合わせ・検査・発話ごとの停止）。Claude がどんな提案を出しても止まることを、決まった返事（モック）でくり返し確かめられる。わざと間違った量・別の位置・2つの提案を返すモックで、受入テスト11・15・16を毎回同じ結果で試せる。
3. 外部通信が無いのでテストが速く、ネットワークや料金の影響を受けない。
4. Claude の部分は「道具の引数（dict）を `session.propose` に渡す」だけの薄い層にしておく。夜に本物の Claude で得た道具の呼び出しを保存し、翌日のモックの正解データにする（仕様5-4）。
5. Claude の接続が失敗しても、プログラムだけで止める判断ができる（失敗を成功と表示しない、受入テスト21）。

## 7. 画面担当との約束（session の使い方）

```python
from voice_teaching.session import Session
s = Session.from_file("samples/dummy/DEMO_PLACE.JBI", max_speed_change_percent=None)

r = s.hear("C00005を選択して", source="voice")   # 発話ごとに必ず最初に呼ぶ
r.status            # "ok" / "ask"（聞き返し） / "stop"（止めた。理由は r.message）
r.facts             # 取り出した事実（位置・量・軸・種類）。解釈として表示してよい
s.select("C00005")                               # 対象を光らせる（候補は作らない）
s.propose({"kind": "shift", "position": "C00005", "axis": "X", "delta_mm": 10})
#   → ok なら s.candidate（jbi.ChangeProposal）と r.comparison、r.message（大きな確認表示の文）
s.compare()          # r.comparison: 行番号・変更前後の行・値・差分・前後の区間・注意書き
s.undo()             # 候補を捨てる。元のジョブ（s.original_bytes）は最初から変わらない
s.log                # 右側の作業ログ（(種類, 文) の並び）
```

- `status` が `ok` 以外のときは、何も変わっていない。`message` をそのまま出す（数字はプログラムが入れた文）。
- 大きな確認表示は `r.message`（または `s.confirmation_text()`）を使う。Claude の文を確認表示に使わない。
- 承認ボタン・書き出しは次の段階で作る。`Session` にはそのためのメソッドが無い。
- `r.blocked_reason` があるときは、候補があっても警告として必ず見せる（`r.candidate_made` で候補の有無を見分ける）。

## 8. 決めてもらうこと（本人）

- 「X方向に10mm」の向き：符号が無いときは＋として読んでいる。確認表示に「+10.000mm」と出る。
- 「パーセント」（カタカナ）を % と同じに扱うか。今は仕様どおり「%」だけを量として読み、「パーセント」は聞き返し。
- 速度を「V=100にして」のように数値で指定する言い方。今は仕様どおり量として読まない（聞き返し）。
- 承認待ちの候補があるときの新しい提案：今は止める。前の候補に足す（累積）か、置き換えるか。
- 速度の1回の変更量の上限（元の速度に対する%）。枠の値が無い間は速度を変えない。
