# 決定の記録：3D・2D の図に、ロボットの台座の中心と正面の向きを出す（2026-11-05 夜）

ブランチ：ui/3d-robot-base（基点 cf0b3fb = integrate/debug-1106）。画面のファイル（view3d.js・index.html・app.js の 2D の図の数行）とテストだけを変えた。サーバー・安全の判定・承認・出力・JOB の生成は変えていない。

唐川さんの言葉（最初の依頼）：「3Dにロボット位置がわかるようにしたい。そうしないとどっちにうごかすかわかりにくい」

## 1回目の決定（11/5 夜）：HC20 を模した静止モデルを出す
もとの仕様の「ロボット本体・関節は描かない」を変えて、HC20 を模したロボットの形（台座・腕・関節）を、静止した 3D モデルとして表示する、と決めた。

- 形のデータは自分で作る（円柱の組み合わせ。安川電機の CAD データ・画像・ロゴは使わない）
- 寸法は目安（届く範囲 約 1700mm に合わせる。唐川さんの確認待ち）、姿勢は決まった1つ、ジョブの再生では動かさない
- 表示・非表示のボタン、「HC20 を模した簡易モデル（メーカーの形状データではありません）」などの注意書き

この決定で一度作った（コミット e3fa13c）。

## 2回目の決定（11/5 夜、プレビューを見て）：シンプルな表示に戻す
唐川さんがプレビュー（17:18 の時点の写し）で HC20 のモデルを見て、**シンプルな表示に戻す**と決めた。

理由：ロボットの形より、JOB の位置と変更内容の見やすさを優先する（モデルを出すと図の大半をモデルが占め、JOB の点と札が小さくなる）。

- HC20 の腕・関節・胴体の 3D モデルは表示しない。モデルを描くコード（寸法・姿勢・部品）、表示・非表示のボタン、モデル用の文は消した
- プレビューで古い文（「ロボット本体・関節は描いていません」）と新しい文が食い違っていた件は、ロボット本体を描かないので、古い文が事実のまま残ることで解消した

## 今の仕様
- **台座の目印**：ロボット座標の原点 (0,0,0)（ジョブはロボット座標。アプリは ///POSTYPE ROBOT・///RECTAN 以外を止める）に、黄色の丸と床の面（Z=0）の点線の輪、札「ロボット（台座の中心）」
- **正面の矢印**：原点から X＋ の向き（安川のロボット座標では X＋ がロボットの正面）へ、黄色の太い矢印と札「ロボットの正面（X＋）」。軸の矢印（X+・Y+・Z+。細い赤・緑・青）とは、色・太さ・矢じり・札で見分ける
- 印の大きさ・矢印の長さは見やすさの目安で、ロボットの大きさ・形ではない。点・経路の下に描き、押しても何も起きない（点を押して選べる）。再生では動かさない
- **今までどおり**：JOB の点・経路・位置番号、XYZ の座標の軸、格子。格子は、点がどれも Z≥0 なら Z=0（台座の面）に置く。Z<0 の点があれば、いちばん下の点の少し下
- **最初の視点と［視点を戻す］**：台座の中心と JOB の点の両方が入る。原点を入れると点が小さくなるので、枠に余りがあれば 2.5 倍まで広げる。点の名前は重なるときに空いた所へずらし、近い点どうしで押せる範囲がほかの点の真ん中を覆わないようにした
- **札の重なり**：台座と正面の札は、点・点の名前・変更の札・回数の札・人が教えた札・右上の窓・軸の文字・左下の文字と重ならない所に置く（無ければ出さない。切れた文字を出さない）
- **2D の図**（Y・Z、X・Z、X・Y）：原点も図の広さに入れ、原点の印と札「ロボット（台座の中心）」。X・Z と X・Y は X＋ の矢印と札「ロボットの正面（X＋）」。Y・Z は X＋ が図の面に垂直なので、矢印を描かず「ロボットの正面（X＋）：この図の面に垂直」
- **向きの言葉**：「上」「右」「手前」などは札に入れない（画面ごとに向きを確かめる仕組みが別の担当で作業中のため）。軸の名前と「ロボットの正面（X＋）」だけ
- **注意書き**：「ロボット本体・関節は描いていません」「動作や干渉を保証するシミュレーターではありません」「この図で離れて見えても、当たらないとは限りません。腕やツールの根元は描いていません」「参考表示であり、実際のロボットの動きではありません」は元のまま。「台座の印は、ロボット座標の原点（0,0,0）の位置です。ロボットの大きさ・形ではありません。」を、確認表示の注意書きと、3D の台座の印にマウスを重ねたときの文に足した。図の下の注意書きには足していない（足すと 1440×900 で注意書きが1行増え、3D が既定の大きさより小さくなって e2e の「3D は 434165d より小さくしない」が通らなかったため）

## 残るリスク
- 台座の丸の大きさや矢印の長さから、ロボットの大きさ・届く範囲を読み取られるおそれ。注意書きで「大きさ・形ではありません」と書いたが、見た目の印象は文より強い
- 原点を図に入れたので、点が小さく見える（DEMO_C_PLACE・DEMO_BUTTON_REPEAT で確かめた。点が原点から遠く、点の広がりが小さいジョブでは、さらに小さい。ホイールで拡大できる）
- 3D の向き（画面の上下・左右がロボットのどちらか）は、画面ごとの確かめがまだ。札に向きの言葉は入れていない
- 「X＋ がロボットの正面」は安川のロボット座標の決まりとして使っている。実機の据え付けで正面の向きが違う場合は、この印と合わない（実機での確かめは唐川さん）
- 内部レビューはサブエージェント（同じ Claude）で行う。外部の独立レビュー（チャッピー）の代わりにはならない
