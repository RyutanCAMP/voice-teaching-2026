# 4ステップの画面（feat/ui-4steps）

唐川さんの方針（2026-11-02）：誰が見ても5秒で使い方が分かり、音声でロボットの動作を変更できる画面。

- ブランチ：`feat/ui-4steps`
- 元にしたコミット：`integrate/mvp-guards` の `f7eddc7`（安全ガードの統合と CHECKER_019 の R1・R6 の修正を含む。feat/mvp へはまだ統合していない）
- 安全ガード側にあとから修正が入ったときは、`integrate/mvp-guards` をこのブランチへマージして取り込む。
  このブランチで変えたのは画面のファイル（`voice_teaching/web/static/` の index.html・app.js・style.css）、テスト、確認用の道具、docs だけ。
  サーバー・検査・承認・出力のプログラムは変えていない。

## 使い方

```
python -m voice_teaching.web --mock   # キーなしで試す。http://127.0.0.1:8765/ を Chrome で開く
```
（`--mock` はモックで試すとき。本物の Claude で動かすときは `--mock` を外し、キー（`.env`）を用意する。キーが無いまま `--mock` なしで起動すると止まります。撮影（`--channel filming`）では `--mock` は使えません）

| ステップ | 画面でやること |
|---|---|
| 1 JOBを読み込む | 最初の画面の大きな枠に .JBI をドラッグ＆ドロップ（クリックしてファイルを選んでもよい）。試すときは `samples/dummy/DEMO_C_PLACE.JBI` |
| 2 位置を選ぶ | 中央の図の点か、右の位置のボタンを押す（選び直すときは位置の「変える」） |
| 3 音声で指示 | 音声の処理方法を選び、大きな 🎤 を押して「この位置を上に10ミリ」と話し、「話し終わった」。入力欄に入った文を確かめて「次へ」 |
| 4 確かめて承認 | 変更前（灰色）と変更後（オレンジ）の経路が自動で再生される。「確認して承認へ」→ 全画面の確認表示で名前を入れて「承認する」→「シミュレーション用に出力」 |

- 上の帯に、今のステップ（オレンジ）と「次にすること」が出る。次に押すボタンは1つだけオレンジで目立たせる。
- 図は3つの向き（Y・Z／X・Z／X・Y）。位置の広がりがいちばん大きい向きを最初に大きく出す（DEMO_C_PLACE は X が一定なので Y・Z）。下の小さな図を押しても切り替わる。
- 「詳細表示」ボタンで、同じ画面の中に作業ログ・解釈の中身・変更候補の差分・位置の一覧・命令の行を開く／閉じる。

## 経路の再生（できること・できないこと）

- **できる**：JOB の命令の順（サーバーが作る `segments`、変更後は `after_segments`）に、位置の点を直線で結んだ線の上を印が動く。変更前 → 変更後の順。今どの命令の行かを横に出す。
- **できない（していない）**：ロボット本体の3Dの動き、腕の姿勢・関節の動き、MOVJ の曲線、PL による角の丸め、速度・加減速・待ち時間（TIMER）、ハンドの開閉（DOUT）、周りの物との距離。
  画面の再生ボタンの下と確認表示に「ロボット本体の動きではありません」と出す。印の速さは画面の上の速さで、ロボットの速度とは関係ない。

## 変えていないこと（安全の線引き）

- 承認は全画面の確認表示の承認ボタンだけ（名前が要る）。声や文字では承認しない。音声は入力欄に入れるだけで自動では送らない。
- 実機用の検査で止まった候補は、承認も出力もできない（R1）。理由は赤で出し、折りたたまない。
- 出力はシミュレーション用だけ（`output/sim/` に `.JBI.txt`）。実機用の出力・転送・ロボットの起動は無い。
- 折りたたまない注意：シミュレーションモードの帯、「元のジョブは変えません…実機用の出力・転送・ロボットの起動はしません」、図の注意（離れて見えても当たらないとは限らない）、再生の限界、音声の処理の注意、止まった理由。
  折りたたんだのは、話し方の例と詳しい操作の説明だけ（`tests/test_ui_4steps.py` で確かめる）。

## 今夜、安全側に決めたこと（唐川さんに確かめてほしい）

1. 候補ができても、確認表示は自動では開かない。先に図で変更前後の経路を再生して見せ、「確認して承認へ」を押してから開く（前の画面は自動で開いていた）。
2. 図の向きの名前は、ロボットの前後左右を推測せず、軸で書いた（「Y・Z（X方向から見る）」など）。「正面」「横」と呼ぶかは実機の置き方を見て決める。
3. 位置のボタンでは、実機用の検査で断られる位置は薄く出す（選ぶことはできる。理由はボタンに重ねると出る）。

## 2回目：説明が要らない画面（2026-11-02 夜）

唐川さんの方針：Apple の製品のように、「説明を増やす」のではなく「説明が要らない画面」にする。合格基準は、初めて使う人が説明なしで操作できること。

| 変えたこと | 中身 |
|---|---|
| 右側は今のステップのカード1枚だけ | 上に大きな見出し（次にすること）。前後のステップのカードは隠す |
| 目立たせる操作は1つだけ | オレンジは1つ（ドロップの枠／マイク／話し終わった／次へ／確認して承認へ／出力／止まったときは元に戻す）。e2e で数える |
| 最初の画面 | 真ん中の大きなドロップの枠だけ（見える文字148文字、ボタン1つ）。JOB は画面のどこへドロップしても読み込む |
| 音声のカード | 位置（「変える」で選び直し）・大きなマイク・入力欄・「次へ」。マイクの方式は選ぶまでだけ出し、選んだ後は「マイクの方式を変える」 |
| 詳細表示へ移したもの | 話し方の例、音声の方式の説明（ブラウザー提供元のサーバーで処理されること）、通信の仕組み（127.0.0.1）、モックの表示、聞き取った文字、解釈、ログ、表、小さな3つの図、再生の詳しい限界 |
| エラー | 大きく「次にすること」（例：「言い方を変えて、もう一度どうぞ」「元に戻すを押して、別の位置を選んでください」）。プログラムの理由はその下に小さく（省略しない） |
| 承認・出力 | 出力ボタンは承認した後だけ出す。確認表示は全画面のまま |
| 重なった点 | 図で同じ所にある点（C00000 と C00007 など）は、位置の「変える」→ 位置のボタンで選べる |

いつも見える所に残したもの（安全に関わる注意）：シミュレーションモードの印、「元のジョブは変えません。実機用の出力・転送・ロボットの起動はしません。」（画面の下）、
図の注意（離れて見えても当たらないとは限らない）、再生の限界（ロボット本体の動きではない）、変更候補の注意、止まった理由、出力ボタンの「合成ジョブだけ・実機に入れない」と
「実機での取り違えを完全に防ぐものではありません」（承認の後、出力ボタンの下）。

安全側に決めたこと（唐川さんに確かめてほしい）：
1. マイクの方式（ブラウザー標準／端末内のみ）は、詳細表示へ移さず、選ぶまではカードに出す。選ばないと録音できない決まり（既定で選ばない）は変えていない。
   「ブラウザー標準は、音声が外部で処理されることがあります。」の一行だけ残し、詳しい説明は詳細表示へ移した。
2. ステップ4（確かめて承認）ではマイクを出さない。録音しながら承認・出力することは、画面の上でも起きない（録音中に承認・出力のボタンを止める処理も残している）。
3. 「1回に動かせる量：仮の上限（確認待ち）20mm」は、音声のカードに小さく残した（話す前に知っておく数字のため）。

スクリーンショット（`docs/ui-4steps/`）：1_start、2_loaded、3_selected、3b_ask（はっきりしない指示）、3c_recording、4_playing、5_engineer、6_confirm（名前が無いとき）、7_blocked（止まった候補の確認表示）。
